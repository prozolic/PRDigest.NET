### [#131297](https://github.com/dotnet/runtime/pull/131297) Optimize Half comparison operators and CompareTo {#131297}
- 作成者: [@tannergooding](https://github.com/tannergooding)
- 作成日時: 2026年07月23日 22:35:13(UTC)
- マージ日時: 2026年07月24日 21:35:26(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-System.Numerics/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-System.Numerics</span></a>
#### 概要
`System.Half` の比較演算子とCompareTo メソッドを最適化しました。主な改善は：
1. `CompareTo` を書き直し、演算子チェーンと冗長なNaN/符号/ゼロチェックを排除
2. AVX2対応環境で `<`、`<=`、`CompareTo` に `(float)Half` 変換を経由した高速パスを追加

AVX2環境では CompareTo が約3.8倍高速化（13.06 us → 3.47 us）、`operator <` は約2倍高速化（4.76 us → 2.41 us）しました。AVX2非対応環境でも従来の実装より高速です。

#### 変更内容
- **src/libraries/System.Private.CoreLib/src/System/Half.cs**
  - `CompareTo(Half)` をNaN処理と単調な符号・大きさ順序キーを用いたビット比較に書き直し（+0と-0を同一のキーに統一）
  - AVX2対応環境で `operator <`、`operator <=`、`CompareTo` に `(float)Half` 変換経由の高速パスを追加
  - 等値演算子（`==`、`!=`、`Equals`）はビット論理のままとした（float変換は測定上遅くなるため）

- **src/libraries/System.Runtime/tests/System.Runtime.Tests/System/HalfTests.cs**
  - `CompareTo_TestData` に符号付きゼロ、非正規化数の符号順序、NaN/無限大順序に関するテストケースを追加

#### パフォーマンスへの影響
**CompareTo（混合データ、AVX2対応機で4096比較/操作）**
- 従来実装：13.06 µs（約3.19 ns/比較）
- ビットキーのみ：7.10 µs（約1.73 ns/比較）
- ビットキー + AVX2 float パス：**3.47 µs**（**約0.85 ns/比較**）→ 約3.8倍高速化

**operator <：約2倍高速化**（4.76 µs → 2.41 µs）

AVX2非対応環境でもビットキー実装により従来の実装より高速（CompareTo 13.06 us → 7.06 us）。

等値演算子は float 変換が測定上遅くなるため（2.16 us → 3.20 us）ビット論理のままとしました。

#### 関連Issue
[#43117](https://github.com/dotnet/runtime/issues/43117)

#### その他

### [#123234](https://github.com/dotnet/runtime/pull/123234) Fix FTP/SSL data stream closure causing protocol violation in .NET 10 {#123234}
- 作成者: [@Copilot](https://github.com/apps/copilot-swe-agent)
- 作成日時: 2026年01月15日 23:33:17(UTC)
- マージ日時: 2026年07月24日 08:01:46(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-System.Net/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-System.Net</span></a>
#### 概要
.NET 10で導入された回帰により、FTPSデータストリームの`SslStream`がクローズされずプロトコル違反が発生していた問題を修正しました。PR #106451でリファクタリングされた`FtpDataStream`が、SSL/非SSL両対応となった際に、`CloseEx`メソッドで`SslStream`のクローズ処理を落としていたのが原因です。修正により、`SslStream`の適切なTLSシャットダウンと、その後の`NetworkStream`のタイムアウト付きクローズを実現しました。

```csharp
// FtpControlStream: SslStream生成時にleaveInnerStreamOpen=true
SslStream sslStream = new SslStream(_dataStream, true, 
    ServicePointManager.ServerCertificateValidationCallback);

// FtpDataStream.CloseEx: SSL/非SSLで異なるストリームの場合
if (_stream != _originalStream)
{
    if ((closeState & CloseExState.Abort) == 0)
        _stream.Close();      // グレースフルなSSLシャットダウン
    else
        _stream.Dispose();    // 中止時はスキップ
}
// NetworkStreamは常にタイムアウト付きでクローズ
```

#### 変更内容
- **`FtpControlStream.cs`**: データストリームの`SslStream`生成時の`leaveInnerStreamOpen`パラメータを`false`から`true`に変更。これにより`SslStream`が自動的に内側の`NetworkStream`をクローズするのを防ぎ、明示的な制御が可能になります。
- **`FtpDataStream.cs`**: `CloseEx`メソッドを修正し、`_stream`と`_originalStream`が異なる場合（SSL時）、`_stream`（`SslStream`）を先にクローズ/破棄してからオリジナルストリームをタイムアウト付きでクローズ。通常クローズと中止時で処理を分離。
- **`System.Net.Requests.Enterprise.Tests`**: FTPS対応の新規テストプロジェクトを追加。SSL/非SSL両シナリオのFTPアップロード/ダウンロード、およびストリーム破棄動作を検証。
- **CI パイプライン**: `enterprise/linux.yml`に`System.Net.Requests`を追加し、エンタープライズテストを自動実行。
