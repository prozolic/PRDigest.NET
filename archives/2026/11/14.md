### [#137530](https://github.com/dotnet/runtime/pull/137530) Fix fork/exec race in ProcessTests.TestId and TestProcessName {#137530}
- 作成者: [@lewing](https://github.com/lewing)
- 作成日時: 2026年11月14日 01:11:59(UTC)
- マージ日時: 2026年11月14日 03:04:23(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-System.Diagnostics.Process/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-System.Diagnostics.Process</span></a>
#### 概要
Linuxにおいて、`Process.Start` 直後に子プロセスの名前を読むと、`/proc/<pid>/stat` の comm がフォーク元の .NET スレッド名（例: `.NET TP Worker`）のままになっている競合状態が原因で、`ProcessTests.TestId` と `ProcessTests.TestProcessName` が不安定になっていました。この修正は **テストのみの変更** で、各アサーションを `RetryHelper.Execute` 内で実行するようにしています。

- **原因**: `Process.Start` は子プロセスが `O_CLOEXEC` の exec-status パイプを閉じた時点で戻りますが、これはカーネルの `begin_new_exec` 内で `exec_mmap()` / `__set_task_comm()` や ELF ローダによる `mm->arg_start/arg_end` 設定より前に起こります。その間、comm は古い名前のままで、cmdline は親の argv もしくは空になり、`GetUntruncatedProcessName` が古い comm にフォールバックします。
- **`TestId` の症状**: 子プロセスの pid が `Process.GetProcessesByName("dotnet")` に含まれない（例: `Collection: [17, 3610] Not found: 3619`）。
- **`TestProcessName` の症状**: `Path.GetFileNameWithoutExtension(".NET TP Worker")` が `""` になり、`Expected: dotnet / Actual: `（空）で失敗する。

#### 変更内容
- `src/libraries/System.Diagnostics.Process/tests/ProcessTests.cs` (+17/-5)
  - `TestId` と `TestProcessName` の各アサーションを `RetryHelper.Execute` 内で実行するように変更。
  - `TestProcessName` では、キャッシュされた名前を再読込するため、各試行で `_process.Refresh()` を呼び出す。
  - アサーションと失敗メッセージは変更なし。リトライを使い切っても失敗する場合は、実際の失敗としてテストが失敗する。
  - `TestId` の Windows 分岐は変更なし。
- 同じ競合を `ProcessStart_OnLinux_UsesSpecifiedProgram*` で修正した #125918 と同じ方針。

#### パフォーマンスへの影響
影響なし（テストのみの変更）。

#### 関連Issue
- Resolves [#137524](https://github.com/dotnet/runtime/issues/137524)
- Relates to [#116051](https://github.com/dotnet/runtime/issues/116051)（`TestProcessName` 失敗の Known Build Error）
- 関連PR: [#125918](https://github.com/dotnet/runtime/pull/125918)

#### その他
- `TestProcessName` は2025年から散発的に失敗しており、2026-11-13 以降は、コンテナ化された Helix 環境（Alpine 3.24 x64/arm64/arm32 の AzureLinux.4 ホスト、Debian 13 arm32 jitstress）でほぼ毎回失敗するようになったとのことです。競合の頻度が上がった理由は特定されていません。
- 検証は macOS arm64 で実施されました。`TestId` と `TestProcessName` の2件が成功し、`ProcessTests` クラス全体（213件）も失敗0、スキップ4で成功しています。Linux の競合自体はローカルで再現しておらず、macOS での実行はリグレッションがないことの確認にとどまります。
- PR の説明と変更は GitHub Copilot の支援を受けて作成されたと記載されています。
