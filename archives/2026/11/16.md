### [#137611](https://github.com/dotnet/runtime/pull/137611) Handle read-only code pages when writing debugger native patches {#137611}
- 作成者: [@tommcdon](https://github.com/tommcdon)
- 作成日時: 2026年11月16日 03:33:25(UTC)
- マージ日時: 2026年11月16日 22:21:24(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Diagnostics-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Diagnostics-coreclr</span></a>
#### 概要
デバッガーがネイティブコードにパッチを書き込む際、対象ページが書き込み不可（W^X の RX ビューは `PAGE_EXECUTE_READ`）だと、従来は `WriteProcessMemory` の失敗が無視されるか assert されるだけでした。本PRは `WriteRemotePatchBytes` ヘルパーを追加し、直接書き込みに失敗した場合は一時的に書き込み可能にして再試行し、元の保護属性を復元します。失敗は呼び出し元へ伝播されるようになります。

対象は、interop デバッグのアンマネージドブレークポイント、skip-breakpoint、およびアウトオブプロセスの `SetThreadContext` によるインプレース単一ステップ経路です。

#### 変更内容
- `src/coreclr/debug/di/rsthread.cpp` (+81/-11)
  - `ApplyRemotePatch` / `RemoveRemotePatch` から使う `WriteRemotePatchBytes` ヘルパーを追加
  - 書き込み成功後に `FlushInstructionCache` を呼び出す
  - `MEM_IMAGE` ページのみ `PAGE_EXECUTE_WRITECOPY` にフォールバックする。マップされたセクションで copy-on-write が起きると、W^X 二重マッピングの RW エイリアスから RX ビューが切り離され、以後の JIT 書き込みが見えなくなるため
  - Checked ビルドでは保護属性の復元失敗を assert する
  - `RemoveRemotePatch` は、書き込み失敗を許容（コードがアンロードされた）とみなすのを、`VirtualQueryEx` が成功しページが未コミットと報告する場合に限定する
- `src/coreclr/debug/di/process.cpp` (+8/-60)
  - `EnableInPlaceSingleStepping` / `HandleInPlaceSingleStep` から重複していた `VirtualProtectEx` ロジックを削除
  - パッチを再適用できない場合、`HandleInPlaceSingleStep` はログ出力と assert を行ったうえで、他スレッドを suspend したまま例外を投げず、単一ステップ状態をクリアして他スレッドを再開する
  - `Setup` / `FixupForSkipBreakpoint` の Checked ビルド assert は維持

影響なし（ベンチマーク結果の記載はありません）。デバッガー内部（DI）の変更で、書き込み失敗時のみ追加の保護属性変更が発生します。

**ILC（コンパイラ）**
- `ObjectWriter`: リンカーがセクション間に thunk を配置するライター（`LinkerPlacesRangeExtensionThunks`）の場合、現在のコードセクションが直接呼び出し到達範囲の半分（arm64/loongarch64 は 64MB、arm は 8MB）を超える前に、同名の新しいセクションを開始します。

#### 概要
Arm/Arm64、LoongArch64、RISC-V64向けJITの `ContainBlockStoreAddress` が、再配置（relocation）が必要な定数（NativeAOTでのfrozenオブジェクトのハンドルなど）を `ADD(base, CNS_INT)` → `LEA(base, offset)` として通常のアドレスモードのオフセットに畳み込んでいた問題の修正です。畳み込まれた定数は再配置なしの `movz`/`movk` で生成されるため、実行時にはILCのプレースホルダー値のままとなり、ブロックコピーがフォールトしていました。xarchは `TryCreateAddrMode` 経由で `ImmedValCanBeFolded` を確認するため影響を受けません。

修正は、オフセット定数が `ImmedValNeedsReloc` の場合に早期リターンし、`ADD` を非containedのまま残して通常の再配置経路で定数を生成するものです。

再現例（preinitialized な `static readonly` 構造体配列を `foreach` で回し、要素をローカルへコピーする（展開されたブロックコピー））:

```csharp
struct Element { public int A, B, C, D, E, F, G, H, I, J, K, L, M; /* 52 bytes */ }

static readonly Element[] s_elements = new Element[] { new Element(0), /* ... */ };

static int SumElements()
{
    int sum = 0, index = 0;
    foreach (Element e in s_elements)
        sum += Checksum(e, index++);   // Checksum は NoInlining で Element を値渡し
    return sum;
}
```

#### 変更内容
- `src/coreclr/jit/lowerarmarch.cpp`（+7）: ARM/ARM64で、再配置が必要な定数をブロックストアのオフセットに畳み込まないよう早期リターンを追加
- `src/coreclr/jit/lowerloongarch64.cpp`（+7）: 同様のチェックを追加
- `src/coreclr/jit/lowerriscv64.cpp`（+7）: 同様のチェックを追加
- `src/tests/nativeaot/SmokeTests/Preinitialization/Preinitialization.cs`（+63）: `TestFrozenStructArrayElementCopy` を追加。クラスがpreinitializeされていることを確認し、全要素・全フィールドのチェックサムを検証（osx-arm64 / linux-arm64 / windows-arm64 のNativeAOTレグで実行）

#### パフォーマンスへの影響
ベンチマーク結果の記載はありません。コード生成の変化として、win-arm64では修正前の再配置なし `movz`/`movk` + `add` が、修正後は `adrp`（HIGH RELOC）+ `add`（LOW RELOC）+ `add` になります。

- EHリージョンは従来、`DW_TAG_try_block`と`DW_TAG_catch_block`のフラットな兄弟エントリとして出力されていました。ネストしたtryやハンドラー内のtryが兄弟と重なっていたため、各tryリージョンを「それを含む最も内側のリージョンの子」として出力するようにしました。

- ファンクレットのsubprogramは`<method>$funcletN`と命名されます（clangが出力する`.cold`部分と同様）。これによりgdbとlldbの両方で、メソッドへのブレークポイントがエントリのみに解決されます。

#### 変更内容
- `DwarfAbbrev.cs`：try/catchの略語（abbreviation）に子要素を持てるようにする変更
- `DwarfBuilder.cs`：subprogramのメタデータにフレーム情報を渡す変更
- `DwarfInfo.cs`（+150/-47）：EHリージョンのネスト出力とFDEごとのsubprogram出力の実装（主要な変更）

- `DwarfDump/Program.cs`（+12/-27）：スモークテストが`il.cpp`でエラー0件を要求するよう変更

### [#133915](https://github.com/dotnet/runtime/pull/133915) JIT: Guard loop cloning against unsigned decreasing IV wraparound {#133915}
- 作成者: [@AndyAyersMS](https://github.com/AndyAyersMS)
- 作成日時: 2026年09月14日 22:02:23(UTC)
- マージ日時: 2026年11月16日 21:59:02(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-CodeGen-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-CodeGen-coreclr</span></a>
#### 概要
JITのループクローニング（loop cloning）において、符号なし（unsigned）の制御変数を持ち、かつ非単位ストライドで減少するループに対する安全性チェックが不十分でした。この場合、IVがラップアラウンドして範囲外アクセスが発生する可能性がありました。本PRでは、init値とlimit値がJIT時定数であり、ラップアラウンドが起こらないと証明できる場合にのみクローニングを行うようにしています。

```csharp
// 例（レビュー指摘内のコード）: init=7, stride=3 の減少ループ
for (uint i = 7; i > 0; i -= 3) { /* 7, 4, 1 の次に wrap する可能性 */ }
```

#### 変更内容
- `src/coreclr/jit/loopcloning.cpp`（+56）: 符号なし減少ループに対する定数境界の安全性チェックを追加。
- `src/tests/JIT/opt/Cloning/DownCounted.cs`（+170/-1）: 配列／Spanを対象としたアンダーフローの回帰テストと、安全に反復できるケースのテストを追加。

#### パフォーマンスへの影響
ベンチマーク結果の記載はありません。該当ループ形状のクローニングが（定数で安全と証明できない場合）行われなくなるため、その範囲でクローニングによる最適化は抑制されます。一方で範囲外アクセスの誤最適化を防ぎます。

#### 関連Issue
[#133824](https://github.com/dotnet/runtime/issues/133824)（Fixes）

#### その他
Copilotレビューでは以下の指摘が挙がっています（最終状態は「Needs a closer look」）。
- `GT_GE` を `GT_GT` と同様に扱うと、包含的なループでラップアラウンドが起こり得る（Critical指摘）。
- `GT_NE` は排他的な減少テストであり、単位ストライドの定数ループ（例: `for (uint i = 7; i != 0; i--)`）が安全にもかかわらず不必要にクローン拒否される可能性がある。
- テストが定数証明パスや非ゼロ剰余（`r != 0`）のケース、リテラルの安全でない `GT` ケースを十分にカバーしていない。
