#### 概要
ILLinkの `UnreachableBlocksOptimizer` において、Cecil が「メソッド末尾まで続く保護領域」を `TryEnd == null` で表現する場合の扱いを修正するPRです。

従来は領域の終端（inclusive）を `IndexOf(TryEnd) - 1` で計算しており、`TryEnd` が null の場合に `-2` となって範囲が空になっていました。その結果、到達可能なハンドラが到達不能と誤判定され、例外句ごと削除されて、元のコードが捕捉していた例外が外へ漏れる可能性がありました。修正では、`TryEnd` が null の場合は最後の命令を終端として扱います。

作成者によると、Roslyn はこのレイアウト（ハンドラが `try` の後ろに続く形でない配置）を生成しませんが、手書きILやILリライタでは発生し得るとのことです。

#### 変更内容
- `src/tools/illink/src/linker/Linker.Steps/UnreachableBlocksOptimizer.cs`: `TryEnd` が null の場合に最後の命令を終端として扱うよう修正（+3/-1）
- `src/tools/illink/test/Mono.Linker.Tests.Cases/UnreachableBlock/Dependencies/EndScopeOnMethod.il`: 新規IL（+74）。到達可能なハンドラ（保持されるべき）と到達不能なハンドラ（従来どおり削除される）を含む
- `src/tools/illink/test/Mono.Linker.Tests.Cases/UnreachableBlock/EndScopeOnMethodWithNullTryEnd.cs`: 新規テスト（+27）。`ipconstprop` が必要で ILTrim が対応していないため、既存の `EndScopeOnMethoEnd` のカバレッジに影響しないよう別のテストドライバとして追加。修正がない場合は失敗する
- `src/coreclr/tools/ILTrim.Tests/ILTrimExpectedFailures.txt`: 上記テストを ILTrim の想定失敗として追加（+1）

#### パフォーマンスへの影響

#### パフォーマンスへの影響

|---|---|---|
| 未使用 | 閉じる | 閉じる |
| `BeginOutputReadLine`/`BeginErrorReadLine` | 閉じる | 閉じる |
| `StandardOutput`/`StandardError` getter | 呼び出し元に委ねる | 呼び出し元に委ねる |
| getterを使わない `ReadAll*` | **開いたまま** | 閉じる |

#### 変更内容
- `Process.cs`（+7/-2）: 標準出力/標準エラーのgetter取得有無を追跡し、呼び出し元が取得していないリーダーを `Dispose` で閉じるようにしました。
- `Process.Multiplexing.Windows.cs`（+15/-0）: Windowsの `ReadAllLines` イテレーターが、列挙終了まで両パイプハンドルへの参照を保持するようにしました（`DangerousAddRef`/`DangerousRelease`）。これはUnix版のイテレーターや `ReadAllText`/`ReadAllBytes` と同じ方式です。この対応がないと、列挙中に `Process` をDisposeした場合、オーバーラップ読み取りが保留中のハンドルが閉じられ、イテレーターのクリーンアップで `ObjectDisposedException` が発生し、リソース解放前に失敗する恐れがありました。

### [#116651](https://github.com/dotnet/runtime/pull/116651) JIT: enable stack allocation of more arrays in R2R {#116651}
- 作成者: [@AndyAyersMS](https://github.com/AndyAyersMS)
- 作成日時: 2025年06月13日 20:16:13(UTC)
- マージ日時: 2026年11月17日 22:43:09(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-CodeGen-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-CodeGen-coreclr</span></a>
#### 概要
ReadyToRun (R2R) でコンパイルされるコードにおいて、`CORINFO_HELP_READYTORUN_NEWARR_1` ヘルパー経由で生成される配列をJITがスタック割り当てできるようにする変更です。あわせて「小さい配列を返すメソッド」へのインライン優先度ブーストを、拡張デフォルトポリシーに加えてデフォルトポリシーにも移し、R2R向けのスタック割り当てテストを有効化しています。

#### 変更内容
- `src/coreclr/jit/objectalloc.cpp` / `objectalloc.h`: R2R用の新しい割り当て種別（`OAT_NEWARR_R2R`）を追加し、既存の配列割り当てと同様に扱うよう `ObjectAllocator` を修正
- `src/coreclr/jit/helperexpansion.cpp`: スタック配列割り当ての展開処理で `CORINFO_HELP_READYTORUN_NEWARR_1` を扱えるよう対応
- `src/coreclr/jit/inlinepolicy.cpp` / `inlinepolicy.h`: `CALLEE_MAY_RETURN_SMALL_ARRAY` の観測を `DefaultPolicy` 側で扱い、インライン判定のブーストを適用（#113236 の一部に対応）
- `src/tests/JIT/opt/ObjectStackAllocation/*`: R2Rでは起きない特定のインライン展開がエスケープ解析に必要なテストメソッドに、aggressive opt指定（`AggressiveOptimization`）を付与。`ObjectStackAllocationTests.csproj` からR2R用の除外設定を削除し、`Runtime_122879.cs` も更新

#### パフォーマンスへの影響
R2Rコードでも配列をスタック割り当てできるようになり、ヒープ割り当てとGC負荷の削減が期待されます。また「小さい配列を返すメソッド」がインライン化されやすくなり、エスケープ解析の成功機会が増える見込みです。ベンチマーク結果は提供情報に含まれていません。
