- `src/coreclr/jit/rangecheck.cpp`: 制約を考慮したサイクル追跡、クリーンアップ（両パスのクリア）、合算での深度カウントを実装
- `src/tests/JIT/Regression_ro_2/Runtime_133818.cs`: 負の初期値の漸化式が負のインデックスを生成するケースの回帰テストを追加（`IndexOutOfRangeException` を期待）

#### 概要
.NETツールチェーンから WebAssembly の [`producers`](https://github.com/WebAssembly/tool-conventions/blob/main/ProducersSection.md) と [`build_id`](https://github.com/WebAssembly/tool-conventions/blob/main/BuildId.md) カスタムセクションを出力するようにするPRです。対象は CoreCLR の `dotnet.native.wasm`、通常の Webcil、R2R Webcil、NativeAOT の再配置可能 Wasm オブジェクトです。アプリケーション向けの Browser 動作は .NET 12 以降で有効化され、それ以前のターゲットフレームワークでは従来の WebAssembly SDK の挙動が維持されます。WASI アプリのリンクや最終的な WASI 実行ファイル／コンポーネントへのメタデータ付与は対象外です。

各成果物ごとのメタデータの扱いは次のとおりです。

| 成果物 | `producers` | `build_id` |
|---|---|---|
| CoreCLR `dotnet.native.wasm` | ランタイムパックの `dotnet-producers.s` を `wasm-ld` がマージ | `wasm-ld` が生成 |
| 通常の Webcil | `WebcilWasmWrapper` が出力 | Webcil ペイロードの SHA-256 |
| R2R Webcil | `WasmObjectWriter` 経由で出力 | 生成モジュールの SHA-256 |
| NativeAOT の再配置可能 Wasm オブジェクト | `WasmObjectWriter` 経由で出力 | なし |

- 出力される `producers` の内容:
  - CoreCLR ネイティブ: `processed-by=CoreCLR`, `sdk=.NET`
  - R2R Webcil: `processed-by=WebCIL`, `sdk=.NET`
  - NativeAOT: `processed-by=ILCompiler`, `sdk=.NET`
  - 通常の Webcil: `processed-by=WebCIL`, `sdk=.NET`
- 各最終 Wasm ファイルが自身の ID を持ちます。ランタイムパックのファイルは元の ID を保持し、ネイティブの再リンクや新規生成の Webcil は生成したコンポーネントが ID を付与します。

- managed 側のレコードには、実行中のコンパイラアセンブリの informational version が入ります。
- Webcil は `language` を意図的に出力しません。マネージドアセンブリは C#、F#、VB、生成 IL など複数言語に由来し得るためです。ネイティブコンパイラの入力は引き続き各自の言語メタデータを提供します。
