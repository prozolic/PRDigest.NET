ライター側は entry point スロットを公開した後、順序保証のある `InterlockedUpdateFlags3` で `HasPrecode` を設定します。一方、リーダー側の2つのロード（`HasPrecode()` → `GetPrecode()` → `GetStableEntryPoint()`）は通常のロードであるため、arm64（Mac M4 など）では並べ替えられ得ます。その場合、`HasPrecode` が立っているのにスロットが古い null のままという状態を観測する可能性があります。null の `Precode*` が `CEEInfo::getFunctionEntryPoint` に渡ると、セル `0x4000` 経由の呼び出しになり、#136918 のダンプと一致します。

#### 変更内容
- `src/coreclr/vm/method.hpp`（+2/-1）
  - `HasPrecode` フラグの読み取りを `VolatileLoad` に変更し、acquire セマンティクスを付与
  - 読み取り順序が必要な理由を説明するコメントを追加
  - `HasPrecode()` の後に `GetPrecode()` を呼ぶすべてのリーダーが対象
  - 内部実装（VM）の変更で、公開 API や互換性への影響はありません

### [#137010](https://github.com/dotnet/runtime/pull/137010) Fix format-string misuse in PAL_GetTransportName {#137010}
- 作成者: [@filipnavara](https://github.com/filipnavara)
- 作成日時: 2026年11月05日 10:32:03(UTC)
- マージ日時: 2026年11月05日 17:05:18(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Diagnostics-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Diagnostics-coreclr</span></a>
#### 概要
`PAL_GetTransportName`（診断サーバーのソケット `dotnet-diagnostic-<pid>-<key>-socket` やデバッガーのトランスポートパイプ名を生成する関数）におけるフォーマット文字列の誤用を修正するPRです。

従来はディレクトリ（`GetTempPathA` の結果、つまり `$TMPDIR`、またはApple環境ではアプリグループのコンテナフォルダー）を連結した文字列を `snprintf` のフォーマットとして使用していました。そのためディレクトリに `%`（例: `TMPDIR=/tmp/%s%n/`）が含まれると、整数をポインターとして読み取ったり `%n` 経由で書き込んだりする可能性がありました。この処理は起動時に毎回実行されます。

```cpp
// 修正前: ディレクトリを含む文字列をフォーマットとして使用
strncat_s(formatBuffer, MAX_TRANSPORT_NAME_LENGTH, IpcNameFormat, strlen(IpcNameFormat));
int chars = snprintf(name, MAX_TRANSPORT_NAME_LENGTH, formatBuffer, prefix, id, disambiguationKey, suffix);
```

修正後はNativeAOTの `ds_rt_aot_transport_get_default_name` と同様に、ディレクトリを `%s` の引数として定数フォーマットに渡します。

#### 変更内容
- `src/coreclr/pal/src/thread/process.cpp`（+12/-12）
  - ディレクトリを `%s` 引数として、リテラルのフォーマット文字列で `snprintf` に渡すよう変更（`-Wformat` による引数チェックも可能に）
  - `strncat_s` の処理と `IpcNameFormat` グローバルを削除
  - disambiguation keyを `%llu` 用に `unsigned long long` へキャスト
  - デバッグ限定の `_ASSERTE` を実際のチェックに置き換え（名前が切り詰められた場合や `snprintf` 失敗時は `name` を空のままにする。これは既存の失敗時の規約）
  - 生のバッファーポインターではなく `PathCharString` からディレクトリを読み取るよう変更（Appleのアプリグループ経路では `GetApplicationContainerFolder` が文字列を再確保し、解放済みメモリを指す恐れがあったため）
  - 名前を格納する余地が残らない `GetTempPathA` の結果を拒否

#### パフォーマンスへの影響
影響なし

#### 関連Issue
なし

#### その他
- セキュリティ面の修正（書式文字列攻撃に相当する問題）で、ランタイム内部（PAL）の実装変更であり公開APIへの影響はありません。CVE番号は記載されていません。

### [#132425](https://github.com/dotnet/runtime/pull/132425) Fix covariant returns scenarios in task-returning methods {#132425}
- 作成者: [@Copilot](https://github.com/apps/copilot-swe-agent)
- 作成日時: 2026年08月17日 18:50:31(UTC)
- マージ日時: 2026年11月05日 18:53:30(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-VM-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-VM-coreclr</span></a> <a style="text-decoration:none;" href="../../labels/runtime-async/index.html"><span style="background-color: #2D0DA0; color: #ffffff; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">runtime-async</span></a>
#### 概要
runtime async において、オーバーライドが `Task`/`Task<T>` そのものではなく**その派生型**（例: `MyTask : Task`）を返す共変戻り値のシナリオを修正します。従来はこのメソッドが task-returning とみなされず Async バリアントを持たなかったため、`await b.M1()` のような呼び出しでオーバーライドではなく**基底実装**が実行されていました。`runtime-async` 機能なしでコンパイルした同じコードは正しくディスパッチされていました。

#### 変更内容
- **`methodtablebuilder.cpp`**: クラスメソッド列挙時に、共変戻り値チェックが必要で、かつ decl が task-returning である virtual `MethodImpl` を検出します。該当メソッドを task-returning として扱い、Async バリアントを1つだけ生成します。その戻り値型は、オーバーライド対象メソッドの要素型（`Task` なら `void`、`Task<T>` なら `T`）です。`T` 内の宣言型の型変数は decl の `TypeSpec` インスタンス化から置換されるため、ジェネリック型/メソッド、閉じた/合成された基底インスタンス化に対応します。
- **新フラグ `AsyncMethodFlags::CovariantForwardingThunk`**: このバリアントは常にサンク（thunk）です。別の virtual スロットへ切り替えてディスパッチを継続するためのもので、`MyTask` を返すメソッドがさらにオーバーライドされうるため、非 async バリアントへの `CALLVIRT` を含みます。共変オーバーライドのみが追加バリアントを必要とし、Task を返さないメソッドは従来どおり async 上は無視できます。
- **`asyncthunks.cpp`**: `EmitCovariantForwardingThunk` が、通常バリアントの `CALLVIRT` の後に、返された Task に対する `AsyncHelpers.TransparentAwait`/`TransparentAwait<T>` を出力します。
- **`FindDeclMethodOnClassInHierarchy`**: `GetAsyncVariant()` ではなく `GetParallelMethodDesc` を使用します。前者は `InstantiatedMethodDesc` の作成や型ロードを行う可能性があり、MethodTable 構築中は許されません（checked ビルドでコントラクト違反）。
- **`readytoruninfo.cpp`**: 戻り値を捨てるサンクと同様に、共変フォワーディングサンクは VM が合成するため R2R ルックアップをスキップし、prestub で IL を一時的に生成します。
- **cDAC / データコントラクト**: 新フラグを `AsyncMethodFlags`（ドキュメントとリーダー）に追加し、サンクは診断対象から隠されます。
- **テスト**: `src/tests/async/` 配下に `custom-task-covariant-return`（C#）と `modified-task-covariant-return`（IL）のテストプロジェクトを追加し、`MethodDescTests.cs` に cDAC のユニットテストを追加しています。PR 説明では、共変オーバーライドの連鎖、`[RuntimeAsyncMethodGeneration(false)]`、ジェネリックメソッド/型、`Task<List<T>>`/`Task<T[]>`、struct 要素型、閉じた/合成された基底インスタンス化などを対象とするとされています。
