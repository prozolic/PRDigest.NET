### [#136978](https://github.com/dotnet/runtime/pull/136978) Fix pre-existing GCInfo decoder correctness issues {#136978}
- 作成者: [@davidwrighton](https://github.com/davidwrighton)
- 作成日時: 2026年11月04日 19:47:44(UTC)
- マージ日時: 2026年11月04日 23:56:05(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-ReadyToRun/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-ReadyToRun</span></a>
#### 概要
GCInfoデコーダー（ReadyToRunツール群とcDAC）に存在していた7件の既存の正確性不具合を、ディスクフォーマット・GCInfo/R2Rバージョン・エンコーダー・Wasm固有の挙動を変更せずに修正します。診断/ツール側のデコーダー修正と回帰テストのみで、GCInfo v6の作業（#135821）には依存しません。

#### 変更内容
- **GCInfoTypes.cs**: LoongArch64の正規化フレームポインタをレジスタ2ではなく22としてデコード。RISC-V64の正規化スタックポインタをレジスタ9ではなく2としてデコード（旧来の非ゼロエンコードも引き続きサポート）。ARM64のEnC固定フレームサイズのエンコード基準を定義。
- **Amd64/GcInfo.cs**:
  - 完全に割り込み可能な遷移オフセットを、バイト単位の範囲と結合する前に非正規化。
  - 半開区間の境界や、複数のスキップ範囲をまたぐ遷移（明示的な割り込み可能範囲を持たないメソッドを含む）を正しくマッピング。
  - 間接セーフポイントのペイロードサイズを「最後に走査したビットマップ」ではなく「参照された最遠のビットマップ終端」で計測（通常ビットマップとRLEビットマップの両方）。
  - ARM64の追加のEnC固定フレームサイズフィールドを読み飛ばし、後続フィールドのアラインメントを維持（潜在的なパーサー問題で、通常のcrossgen2コンパイルではEnCは有効にならない）。
- **GCInfoDecoder.cs（cDAC）**: ヘッダーを返す前にoutgoing/scratchパラメーター領域をデコード。ネイティブのreverse-P/Invokeデコード境界を保つため、別の停止ポイントを使用。
- **テスト**: `GcInfoRegressionTests.cs`にR2R回帰テスト36ケース、`GCInfoHeaderTests.cs`にcDACテスト（記載上7ケース、Copilot概要では5ケース）を追加。

#### パフォーマンスへの影響
影響なし（デコーダーの正確性修正のみで、ベンチマーク結果の記載なし）。

#### 関連Issue
なし
（#135821のGCInfo v6作業とは独立している旨が記載されています）

#### その他
- 検証（Linux x64上、警告・エラーなし）:
  - R2Rテスト: 179件成功、0件失敗、既存のスキップ15件。新規36ケースを含む。
  - cDACテスト: 3,969件成功、0件失敗、スキップなし。新規ケースを含む。
- 修正前のテストでは、R2Rで28件、cDACで5件の失敗を確認。
- フィクスチャはAMD64、ARM32、ARM64、LoongArch64、RISC-V64のデコードを検証しますが、各アーキテクチャ上でのネイティブ実行テストではありません。
- 追加の回帰テストとして、ジェネリックコンテキスト検索がoutgoing領域を読まないこと、スリムヘッダーのデコードがセーフポイント数を読まないことを確認。
- このPRと説明はGitHub Copilotの支援で作成されています。

  - 中間コピーを除去（既存のセクション長の検証は維持）

`GetFieldRvaData` は以下から呼び出されます（いずれもコンパイラツール側の内部実装）。
- `FieldRvaDataNode.GetData`（オブジェクト出力時）
- `TypePreinit`（静的コンストラクタのプリイニット時）
- `CorInfoImpl.TryReadRvaFieldData`（`getStaticFieldContent`、JITによるメソッドコンパイル中。ILCとcrossgen2の両方）

#### 関連Issue
なし

#### その他
- 公開APIの変更や互換性への影響に関する記載はなく、ツール内部（共有型システム）の実装変更です。
- 同様のパターン（`GetReader` による範囲限定読み取り）は、ツール内の他の `GetSectionData` 呼び出し元（例：`Win32Resources/ResourceData.cs`）でも既に使われています。

### [#130367](https://github.com/dotnet/runtime/pull/130367) \[cDAC\] Remove DT_CONTEXT from DBI layer {#130367}
- 作成者: [@rcj1](https://github.com/rcj1)
- 作成日時: 2026年07月08日 17:53:40(UTC)
- マージ日時: 2026年11月04日 21:05:24(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Diagnostics-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Diagnostics-coreclr</span></a> <a style="text-decoration:none;" href="../../labels/area-Diagnostics-cdac/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Diagnostics-cdac</span></a>
#### 概要
cDAC（および DAC）内にターゲット固有の知識を閉じ込めるため、DBI 層から `DT_CONTEXT` を削除する変更です。コンテキストに関する操作（サイズ取得、レジスタ読み書き、コピー、比較など）を `IDacDbiInterface` 経由の新 API として提供し、アーキテクチャ別だった `(arch)/cordbregisterset.cpp` を共通実装に置き換えます。

- ホストとターゲットが同一であるライブ interop デバッグでは `DT_CONTEXT` を `T_CONTEXT` に置換
- ホストとターゲットでレイアウトが異なり得る場合は、構造体の代わりにポインタと明示的サイズを持つ不透明な `ContextBuffer` を使用し、レイアウトの解釈は DacDbi に委譲

追加された DacDbi API（PR 説明より）:

```csharp
int GetTargetContextSize(Interop.BOOL hasExtendedRegisters, uint* pSize);
int GetFullContextFlags(uint* pFlags);
int WriteRegistersToContext(ContextBuffer contextBuffer, CorDebugRegister* regs, uint nRegs, nuint* values);
int ReadRegistersFromContext(ContextBuffer contextBuffer, CorDebugRegister* regs, uint nRegs, ulong* pValues);
int GetAvailableRegistersMask(Interop.BOOL fActive, Interop.BOOL fQuickUnwind, uint regCount, byte* pAvailable);
int ConvertJitRegNumToCorDebugRegister(uint jitRegNum, CorDebugRegister* pReg, Interop.BOOL* pIsAmbientSP);
int WriteFloatRegisterToContext(ContextBuffer contextBuffer, CorDebugRegister reg, byte* pValue, uint valueSize);
int ContextHasExtendedRegisters(ContextBuffer contextBuffer, Interop.BOOL* pResult);
int CompareControlRegisters(ContextBuffer contextBuffer1, ContextBuffer contextBuffer2, Interop.BOOL* pResult);
int CopyContext(ContextBuffer destinationContext, ContextBuffer sourceContext, ContextCopyMode copyMode, uint flags);
```

#### 変更内容
- **DacDbi インターフェース（IDL / ネイティブ / マネージド）**
  - `dacdbi.idl`、`dacdbiinterface.h`、`IDacDbiInterface.cs` に上記 API を追加
  - `DT_CONTEXT` typedef を削除し、コンテキスト引数を `BYTE*` に変更
  - `Debugger_STRData::ctx` も `BYTE*`（不透明な対象コンテキストバイト列）に変更
- **DAC 実装**
  - `dacdbiimpl.cpp` に新 API を実装（レジスタ可用性、JIT レジスタ番号マッピング、浮動小数点処理など。+744 行）
  - `dacdbiimplstackwalk.cpp` のスタックウォーク系エントリポイントを `BYTE*` 受け取りに変更し、内部で `DT_CONTEXT` に reinterpret
- **DBI（right side）**
  - `rsstackwalk.cpp`、`rsregsetcommon.cpp`、`shimstackwalk.cpp`、`shimpriv.h`、`rspriv.h`、`valuehome.cpp`、`process.cpp`、`rsthread.cpp` で、内部状態を不透明バッファ化し、`CopyContext` やレジスタ読み書きを DAC 経由に変更
  - `process.cpp` にターゲットコンテキストサイズのキャッシュを追加
  - `module.cpp` の JIT レジスタ番号 → `CorDebugRegister` 変換を DAC 経由に変更
  - `DbiGet/SetThreadContext` を `T_CONTEXT` ベースに統一（`stdafx.h`、`cordb.cpp`）
- **共通レジスタセット化**
  - 各アーキテクチャの `cordbregisterset.cpp` を削除し、共通の `cordbregisterset.cpp` を追加
  - 不要になった `floatconversion.S/.asm` を削除、CMake を更新
- **debug 共通部**
  - `debug/inc` および `debug/shared` の `primitives` 系ヘッダ/実装で `DT_CONTEXT` を `T_CONTEXT` に変更
  - `dbgipcevents.h` からアーキテクチャ別の浮動小数点レジスタ数と SP/FP アドレスヘルパーを削除し、`CORDB_MAX_FLOAT_REGISTERS` を導入
  - `debugger.cpp`、`controller.cpp` の `DT_CONTEXT` キャストを削除
- **cDAC マネージド側コンテキストモデル**
  - 各アーキテクチャの Context クラス、`IPlatformContext`、`IPlatformAgnosticContext`、`ContextHolder` に、レジスタのコピー対象（スカラー/ワイド）メタデータや拡張レジスタ関連プロパティを追加
  - `RegisterType.Extended` を追加
  - LoongArch64 のコンテキストサイズと浮動小数点レイアウトを更新
