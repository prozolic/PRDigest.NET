#### 概要

#### 変更内容
- `eng/Versions.props`: MsQuic の共有バージョンを 2.5.10 → 2.5.11 に更新（+1/-1）
  - OpenSSL（テスト用）と Schannel（製品用）の両パッケージがこのバージョンを参照します。
  - NuGet 監査の警告ポリシーは維持しており、警告の抑制（suppression）は行っていません。

マネージドコードの変更はなく、依存パッケージのパッチバージョン更新のみです。公開 API や互換性（破壊的変更・非推奨化）への影響は記載されていません。

### [#135486](https://github.com/dotnet/runtime/pull/135486) JIT: copy large local structs through their address when decomposing {#135486}
- 作成者: [@EgorBo](https://github.com/EgorBo)

#### 概要
JITのLowering段階で、GC参照を含む構造体のコピーを個別のストアに分解する際、ローカル変数のソースを `LCL_FLD` ノード経由で読み取っていました。`LCL_FLD` のオフセットは16ビットに制限されているため、64 KiBを超える構造体ではオフセットが折り返され、誤ったデータを読み取って64 KiB以降のフィールドが欠落していました（Checkedビルドではアサート）。

本PRでは、ローカルのフィールドをすべて `LCL_FLD` としてエンコードできない場合（`IsValidLclAddr` が偽の場合）、ローカルのアドレスを一度取得し、そのアドレス経由で各部分をロードするよう修正しています。これは間接ソースに対して既に使われているパスと同じです。

#### 変更内容
- `src/coreclr/jit/lower.cpp`（+18/-2）: 64 KiBを超えるローカル構造体のコピー時に、`LCL_FLD` のオフセット折り返しを避けるため、アドレス経由でロードするパスを追加。
- `src/tests/JIT/Regression_ro_2/Runtime_133581.cs`（+64/-0）: ヒープフィールドおよび `ref` を宛先とするコピーで、64 KiB境界を超えるフィールドが正しくコピーされることを検証する回帰テストを追加。

#### パフォーマンスへの影響

### [#135485](https://github.com/dotnet/runtime/pull/135485) JIT: model the signed Log2 fallback as throwing {#135485}
- 作成者: [@EgorBo](https://github.com/EgorBo)
- 作成日時: 2026年10月09日 10:02:55(UTC)
- マージ日時: 2026年10月10日 16:46:49(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-CodeGen-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-CodeGen-coreclr</span></a>
#### 概要
符号付きの `int.Log2` / `long.Log2` は `x < 0 ? INTRINSIC(Log2, x) : lzcnt-based result` としてインポートされ、フォールバック側のノードは後に例外をスローするマネージド呼び出しへ書き換えられます。しかしこのフォールバックノードは手動で `GTF_CALL` が設定されているだけで、`OperExceptions` が例外なしと報告し、副作用チェックも本物の呼び出しとしてしか扱わないため、戻り値が未使用の場合にデッドストア除去で `ArgumentOutOfRangeException` ごと削除されていました。本PRはこのフォールバックを「例外をスローし得る」ものとして扱うよう修正します（JIT内部の修正で、公開APIの変更はありません）。

また、フォールバックを保持するようにしたことで顕在化した `fgExpandQmarkStmt` の潜在バグ（then側のみのqmarkで、条件を反転しているにもかかわらず then/else の確率が逆のエッジに割り当てられ、then側が稀な場合にプロファイルデータが不整合になる）も合わせて修正しています。

#### 変更内容
- `src/coreclr/jit/gentree.cpp`: `OperExceptions` で `Log2` フォールバックの intrinsic が例外をスローし得ることを報告するよう変更（+6/-1）。
- `src/coreclr/jit/importercalls.cpp`: フォールバックノードに `GTF_EXCEPT` を付与（+1/-1）。
- `src/coreclr/jit/morph.cpp`: `fgExpandQmarkStmt` の then/else の確率を正しいエッジに割り当てるよう修正（+5/-4）。
- `src/coreclr/jit/valuenum.cpp`: 値番号付けで、スローし得る `GT_INTRINSIC` に関する `NamedIntrinsic` のガイダンスに従い、フォールバックに不透明な例外セット（opaque exception set）を付与（+10/-0）。
- `src/tests/JIT/Regression_ro_2/Runtime_133965.cs`: 符号付き `Log2` の結果を破棄した場合の回帰テストを追加（+52/-0）。

#### パフォーマンスへの影響

  - `Program.cs`でPDBを書き出すようにしました。
  - `--debug-mode`のヘルプ文を修正しました。
- **出力ファイル処理の挙動**
  - イメージを先に書き込んでクローズしてから、PDBを書きます。
  - PDBなしでイメージを書いた場合、既存の`<output>.pdb`は「置き換え前のイメージのCodeViewエントリがそのPDBのidを指している場合のみ」削除します。それ以外のファイルは保持します。
  - 出力パスとPDBパスが衝突する場合（`-OUTPUT=Min.pdb -DEBUG`）はエラーにして何も書きません（ネイティブはイメージをPDBで上書き）。比較はWindows/macOSでは大文字小文字を無視します。

| 修正後 | 36.4 us/call |

競合のない場合のミューテックスによるオーバーヘッドは約2%です。並行呼び出しは意図的に直列化されます（Mach経由のレジスタ状態クエリを並行発行することがデッドロックの原因であるため）。
