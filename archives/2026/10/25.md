### [#136444](https://github.com/dotnet/runtime/pull/136444) Simplify sample profiler native pointer conversion {#136444}
- 作成者: [@steveisok](https://github.com/steveisok)
- 作成日時: 2026年10月25日 17:31:02(UTC)
- マージ日時: 2026年10月25日 21:08:28(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Tracing-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Tracing-coreclr</span></a>
#### 概要
サンプルプロファイラ関連テストにおけるネイティブポインタ変換を簡素化する、テスト専用のワンライナー修正です。#136433 のバックポートに対する Jan 氏のレビュー指摘を反映し、`IntPtr` と `nint` が同一型であることから `IntPtr stack = (nint)address;` を用いる形に整理しています。

- 既存の符号拡張に関するコメント、`ulong` によるアドレス表現、スタック読み取りロジックは変更なし
- プロジェクトはデフォルトで unchecked 演算のため、ネイティブ幅への切り詰め変換の挙動は維持される
- クラッシュ修正自体は #136433 に含まれており、本 PR 単体ではクラッシュを修正しない

```csharp
IntPtr stack = (nint)address;
```

#### 変更内容
- `src/tests/tracing/eventpipe/eventsvalidation/SampleProfilerSampleType.cs`（+1/-1）: ポインタ変換を `(nint)address` を使う形に簡素化

同じ修正は release/11.0 向けバックポート #136440 と release/10.0 向けバックポート #136441（release/10.0 ではヘルパーが `GCEvents.cs` にある）にも反映済みです。

#### パフォーマンスへの影響
影響なし（テストコードのみの変更。旧コードと簡素化後のコードは同一の IL `ldarg.0; conv.i; ret` を出力することを確認済み）。

#### 関連Issue
- [#136433](https://github.com/dotnet/runtime/pull/136433)（クラッシュ修正本体）
- [#136440](https://github.com/dotnet/runtime/pull/136440)（release/11.0 バックポート）
- [#136441](https://github.com/dotnet/runtime/pull/136441)（release/10.0 バックポート）

#### その他
検証内容:
- 3ブランチすべてで MSBuild により実際のテストプロジェクトを評価し、ARM/ARM64 の Debug・Checked・Release で `CheckForOverflowUnderflow=false` であること、キャスト周囲に checked ブロックがないことを確認
- ARM64 上で .NET 10.0.9 と .NET 11.0.0-preview.6.26322.101 を用いたキャスト等価性の検証プログラムを実行。ネイティブ幅の 10 ベクタと、32bit 切り詰めをシミュレートした 10 ベクタ（符号拡張された上位ビットを持つポインタ `0xFFFFFFFFD2345678` を含む）がパスし、checked 変換のコントロールは期待どおり例外をスローした
- 3ブランチすべてで `git diff --check` がパス

制限事項:
- ランタイム全体の再ビルドや EventPipe テストハーネスの実行は未実施
- 32bit の確認は ARM64 上での切り詰めシミュレーションであり、実際の ARM32 での実行ではない
- 検証用プログラムは PR に含まれない

### [#136433](https://github.com/dotnet/runtime/pull/136433) Fix SampleProfilerSampleType overflow on 32-bit platforms {#136433}
- 作成者: [@pcshrosbree](https://github.com/pcshrosbree)
- 作成日時: 2026年10月25日 07:19:32(UTC)
- マージ日時: 2026年10月25日 14:02:20(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Tracing-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Tracing-coreclr</span></a> <a style="text-decoration:none;" href="../../labels/community-contribution/index.html"><span style="background-color: #c2e0c6; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">community-contribution</span></a>
#### 概要
linux-arm Checked で断続的に発生していた `SampleProfilerSampleType` テストの `OverflowException` を修正する PR です。32ビットプロセスでスタックアドレスが `0x80000000` 以上に配置された場合、TraceEvent 3.1.28 が `IntPtr` から `ulong` へ変換する際に符号拡張され（`0xFFFFFFFF_xxxxxxxx`）、テスト側の `checked((nuint)address)` が例外を投げていました。変換を `unchecked((nint)address)` に変更し、ネイティブ幅のビットのみを保持するようにしています。64ビット環境での結果は変わりません。

#### 変更内容
- `src/tests/tracing/eventpipe/eventsvalidation/SampleProfilerSampleType.cs`（+2/-1）
  - スタックアドレスの変換を `checked((nuint)address)` から `unchecked((nint)address)` に変更

#### パフォーマンスへの影響
影響なし（テストコードのみの変更）。

#### 関連Issue
- [#136197](https://github.com/dotnet/runtime/issues/136197)（Fixes）
- [#135219](https://github.com/dotnet/runtime/pull/135219)（`SampledStacksOmitGCPollHelpers` を追加した PR。このテストが失敗する原因となった変更）

#### その他
- 作成者は linux-arm 上でテストを実行できておらず、x64 上で 32ビット形式の変換を模した小さなプログラムで確認しています（旧変換は `OverflowException`、新変換は `0xB6A01000` を返す）。実際の検証は本 PR の linux-arm CI で行う必要があります。失敗が断続的なため、1回の成功だけでは根拠として弱いと作成者も述べています。
- #135219 は release/11.0（#136077）と release/10.0（#136091）にバックポートされているため、本修正も同様のバックポートが必要です。
- 作成者によると、本変更は AI（Anthropic Claude、OpenAI Codex による確認）の支援を受けて作成されています。

```csharp
// 修正後の変換（概念）
// 32ビットでは符号拡張された値でも例外にならず、ネイティブ幅のビットのみ保持される
nint value = unchecked((nint)address);
```
