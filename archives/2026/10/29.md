### [#136650](https://github.com/dotnet/runtime/pull/136650) Fix NaN sign comparison for Sum/Average/Product in TensorValueReductionsPreserveScalarOrder {#136650}
- 作成者: [@lewing](https://github.com/lewing)
- 作成日時: 2026年10月29日 18:22:46(UTC)
- マージ日時: 2026年10月29日 23:30:46(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-System.Numerics.Tensors/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-System.Numerics.Tensors</span></a>
#### 概要
`TensorValueReductionsPreserveScalarOrder` テストが linux-arm64 の `libraries-jitstress` で失敗する問題の修正です。入力 `[-Inf, +Inf, -0.0, 0.0, NaN, -3]` に対し、`-Inf + +Inf` が生成する正規NaNと入力の `double.NaN` が結合される際、どちらのNaNが伝播するかはオペランド順に依存し、JitStressがその順序を変えます。そのため `Tensor.Sum` のアサーションで期待値 `0x7FF8000000000000` (+NaN) に対し実際は `0xFFF8000000000000` (-NaN) となっていました。#136438 (Dot) と #136552 (CosineSimilarity) の続編にあたるテスト専用の変更で、プロダクションコードの変更はありません。

#### 変更内容
- `src/libraries/System.Numerics.Tensors/tests/TensorTests.cs` (+3/-3)
  - 既存の `AssertBitsOrNaN` ヘルパーを使うよう、以下3つのアサーションのみ変更しています。
    - `Tensor.Sum`: `-Inf + +Inf` が正規NaNを生成する（実際に失敗していた箇所）
    - `Tensor.Average`: `Sum / n`（Sumを緩和すると次に失敗する）
    - `Tensor.Product`: `Inf * 0` が正規NaNを生成する（ローカルでは失敗しなかったが同様の順序依存あり）
  - `Norm`、`Distance`、`StdDev`、min/max系は、入力NaNのみが伝播する、または `Abs` で符号が正規化されるため、厳密なビット比較のまま変更していません。

#### パフォーマンスへの影響
影響なし（テストコードのみの変更）。

#### その他

  - 修正前は `DOTNET_JitStress=1` または `2` と `DOTNET_TieredCompilation=0` の組み合わせでCIの失敗を再現しました。

- 移行ツール（ILLink アナライザー/コードフィックス、interop・System.Text.Json ジェネレーター）の修正
- `MemorySafetyRulesVersion` による v2 検出
- `eng/memorySafetyRules.targets` による opt-in 機構の追加


- **移行ツール（`src/tools/illink`、interop ジェネレーター）**

  - `UnsafeMigrationFixAllProvider` を追加し、診断ごとに個別の修正を適用。従来は、1 つの修正不能な `IL5005` により `dotnet format` のパス全体が何も行われなくなる問題があった。

  - #131484 の `IL5009`/`IL5010` と safety コメント追加フィクサー（`AddSafetyCommentCodeFixProvider.cs`）を復活。スタブは `// SAFETY: To be audited`、インラインの `/* SAFETY: */` も認識。
- **オプトイン基盤**
  - `eng/memorySafetyRules.targets` と `eng/unsafeMigration.globalconfig` を追加し、`Directory.Build.targets` から参照。
  - `EnableUnsafeMigrationAnalyzers=true` で `IL5005`〜`IL5010` を有効化（既定は無効）。
  - `UnsafeMigrationProject`/`UnsafeMigrationTargetFramework` で移行対象を単一 TFM に絞れる（`dotnet format -f` は参照プロジェクトも再ターゲットするため不可）。
  - `AllowUnsafeBlocks` は各ライブラリの判断のまま。
  - 既存の ref アセンブリ（`System.Runtime`、`System.Memory`、`System.Numerics.Vectors`、`System.Runtime.InteropServices` など）と System.Text.Json テストの opt-in をプロパティ方式へ移行。

#### 概要
JITの範囲チェック除去を強化するPRです。`Span.Slice` などで冗長になっている境界チェックを、より多くのケースで除去できるようにします。#112953 をクローズします。

```csharp
static ReadOnlySpan<char> Test(ReadOnlySpan<char> span, int offset)
{
    if ((uint)offset < (uint)span.Length)
        return span.Slice(offset + 1); // 範囲チェックが除去される
    return span;
}
```

主な技術的ポイント:
- 符号なし比較についても VN 同士の relop assertion を作成するようにしました。あわせて、`X < Y`（符号付き/符号なし）から `(X + 1) <= Y` / `(X + 1) > Y` を畳み込めるようにしています。`X < Y` が成り立つ場合、`X + 1` はオーバーフローしないためです。
- Span の長さを配列長と同様に checked bound として扱います。これにより、たとえば `length <= span.Length - 4` の後の Slice チェックを畳み込めます。
- 既存バグの修正: `(uint)i < (uint)len` の最適化で「IsVNCheckedBound は決して負にならない」と仮定していましたが、この仮定は誤りでした。

#### 変更内容
- `src/coreclr/jit/assertionprop.cpp` (+36/-20): 符号なし比較を含む relop assertion の生成と、それを利用した畳み込みの処理を変更
- `src/coreclr/jit/compiler.h` (+13/-13): 関連する宣言・定義の変更
- `src/coreclr/jit/valuenum.cpp` (+10/-0): Span の長さを checked bound として扱うための処理を追加
