- `src/libraries/Common/src/Interop/Interop.Ldap.cs`: `LDAP_TIMEVAL` のフィールド型を `CLong` に変更（+3/-2）
- `src/libraries/System.DirectoryServices.Protocols/src/System/DirectoryServices/Protocols/Interop/LdapPal.Linux.cs`: Linux向けPALの該当箇所を調整（+2/-6）
- `src/libraries/System.DirectoryServices.Protocols/src/System/DirectoryServices/Protocols/ldap/LdapConnection.Linux.cs`: タイムアウト構造体の設定部分を更新（+2/-2）

### [#136585](https://github.com/dotnet/runtime/pull/136585) Do not return the DNS TCP buffer to the pool twice when growing it fails {#136585}
- 作成者: [@EgorBo](https://github.com/EgorBo)
- 作成日時: 2026年10月28日 15:47:17(UTC)
- マージ日時: 2026年10月28日 23:50:53(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-System.Net/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-System.Net</span></a>
#### 概要
DNSのTCP応答の長さプレフィックスが借用済みバッファより大きい場合、`SendTcpQueryAsync`/`SendTcpQuerySync` は `ArrayPool` にバッファを返却してから、同じ変数に大きなバッファを再度 `Rent` していました。この `Rent` が例外（例：`OutOfMemoryException`）をスローすると、変数は返却済みの配列を指したままになり、catchブロックで同じ配列が二重に返却されます。その結果、プールが同一配列を独立した2つの借用者に渡す可能性がありました。本PRは、先に大きなバッファを `Rent` し、その後で古いバッファを返却して新しいバッファに切り替えるよう順序を変更し、変数が常に所有中の配列を指し、返却が1回だけになるようにします。

#### 変更内容
- `src/libraries/System.Net.NameResolution/src/System/Net/DnsResolverPal.Managed.cs`（+4/-16）
  - TCPバッファ拡張時の処理順序を修正：新しい大きなバッファを先に `Rent` → 古いバッファを返却 → 変数を新バッファに切り替え
  - これにより、拡張失敗時に二重返却となる問題を解消（内部実装の修正であり、公開APIの変更はなし）

#### パフォーマンスへの影響

#### 変更内容
- `src/libraries/Common/src/Interop/Windows/SspiCli/SecuritySafeHandles.cs`（+23/-3）

  - ハンドルが閉じられている場合は `null` を返すよう変更
