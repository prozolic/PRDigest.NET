### [#135130](https://github.com/dotnet/runtime/pull/135130) Seed Debug Roslyn compiler caches from rolling builds {#135130}
- 作成者: [@agocke](https://github.com/agocke)
- 作成日時: 2026年10月02日 21:38:26(UTC)
- マージ日時: 2026年10月03日 01:22:06(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Infrastructure/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Infrastructure</span></a>
#### 概要
ローリングビルドのDebugバリアント向けRoslyn コンパイラキャッシュのシーディング機能を追加します。Linux x64、Linux musl x64、macOS arm64 の3つのプラットフォーム向けDebug構成の`CoreCLR_AllSubsets`ローリング専用ビルドを新規追加し、DebugおよびReleaseのRoslyn キャッシュエントリを分離して、各構成が独立してイミュータブルキャッシュをシードできるようにします。既存のv1エントリは復元フォールバックとして残ります。

#### 変更内容
- **eng/pipelines/runtime.yml**: Linux x64、Linux musl x64、macOS arm64向けローリング専用Debug ビルドレグを追加（+19行）
- **eng/pipelines/coreclr/templates/setup-roslyn-cache.yml**: Roslyn キャッシュをDebug/Release構成で分離してバージョニング。v1 フォールバック互換性を維持（+6行/-4行）

#### パフォーマンスへの影響
関連する #133748 のRoslyn キャッシュ検証では、`libs.tests`でキャッシュ利用時に4m53s、未使用時に6m32sを計測（25.25%高速化）。Debug固有のヒット率は、最初のローリングDebugビルドがキャッシュをシードした後に測定可能になります。

#### 関連Issue
[#133748](https://github.com/dotnet/runtime/issues/133748)

#### その他
- 設定オプション化により、PR ビルドに対応するDebugローリングビルドが独立したキャッシュをシードでき、CI パイプラインの効率化を実現します
- Copilot審査での評価：推奨承認（変更が既存パイプライン設定と一貫性を保つ）

### [#135077](https://github.com/dotnet/runtime/pull/135077) Add FTPS directory listing regression test {#135077}
- 作成者: [@wfurt](https://github.com/wfurt)
- 作成日時: 2026年10月02日 02:30:39(UTC)
- マージ日時: 2026年10月03日 04:29:11(UTC)

#### 概要
`FtpWebRequest`の`ListDirectoryDetails`メソッドにおける、TLS有無別の同期リクエスト処理に関する回帰テストを追加します。返されるリスト形式がプレーンテキストであること、アップロードされたフィクスチャが含まれていること、`FtpStatusCode.ClosingData`で完了することを検証します。これは#134130で報告されたシナリオに対応しており、製品側の修正は既に#123234でmainに統合済みです。

#### 変更内容
- **FtpWebRequestStreamDisposalTest.cs**: TLS有無別の`FtpListDirectoryDetails`に対するテストケースを追加（+57行）。プレーンテキスト形式の検証、フィクスチャ含有確認、正しいステータスコード（226 ClosingData）の検証を実装。アップロード済みフィクスチャはテスト失敗時も確実にクリーンアップされるよう構成。
- **README.md**: エンタープライズテスト内の追加FTPS ディレクトリリスト検証カバレッジをドキュメント記載（+1行）

#### パフォーマンスへの影響
影響なし

#### 関連Issue
[#134130](https://github.com/dotnet/runtime/issues/134130)、[#123234](https://github.com/dotnet/runtime/pull/123234)

#### その他
- 本テストは負のコントロールとしても機能：古い同期ストリーム選択ロジックで再ビルドした場合、非TLS環境では成功するが、TLS環境では`StreamReader.ReadToEnd`で`ObjectDisposedException`が発生することを確認済み
- 実環境検証済み：.NET 10.0.0ではステータスコード226返却後もTLS暗号化データが返されていたが、.NET 11 RC1では期待通りプレーンテキスト形式のリスト情報を返すことを確認

WebAssembly (Wasm) コードジェネレーションの完成度向上に伴い、`JitWasmNyiToR2RUnsupported` フォールバック機構を削除します。これにより、crossgen2がNYI_WASMに達した場合に黙ってメソッドを省略するのではなく、通常のJITコンパイル失敗として表示され、残存する実装ギャップが可視化されます。

#### 変更内容
- **JIT設定の削除**: `jitconfigvalues.h`から`JitWasmNyiToR2RUnsupported`設定を削除、`error.h`から関連エラー処理を削除
- **コードジェン変更**: `codegenwasm.cpp`からフォールバック処理を削除（5行削除）
- **クロスジェン設定**: `crossgen-corelib.proj`からフォールバック引数を削除
- **ビルド設定更新**: 
  - `Microsoft.NET.Sdk.WebAssembly.Browser.CoreCLR.targets`からSIMDフォールバック引数を削除
  - `WasiApp.CoreCLR.targets`から同様の引数を削除
  - `CLRTest.CrossGen.targets`からテスト設定の調整
- **SuperPMI対応**: `superpmi.py`からWasm関連のフォールバック処理を削除

#### パフォーマンスへの影響
影響なし。本変更はコンパイル時の動作を改善し、実行時パフォーマンスへの直接的な影響はありません。

#### 関連Issue
なし

- 公開API（ランタイムのパブリックインターフェース）への影響なし
- 内部的なJIT設定とクロスジェン周辺のみの変更

### [#133684](https://github.com/dotnet/runtime/pull/133684) \[aw\] Make CI KBE issue search deterministic {#133684}
- 作成者: [@vitek-karas](https://github.com/vitek-karas)
- 作成日時: 2026年09月11日 11:39:21(UTC)
- マージ日時: 2026年10月03日 07:13:09(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-skills/index.html"><span style="background-color: #1ddbf3; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-skills</span></a>
#### 概要
CI KBE（Known Build Errors）イシュー検索を決定論的にするため、リポジトリスコープのMCPラッパースクリプトを導入し、検索結果の決定重複検出前に全候補を`issue_read`で検査することを義務付けます。組み込みイシュー検索アクセスを削除し、ラッパーパス強制と失敗時閉鎖動作をスキャナー評価で強化します。

#### 変更内容
- **search-kbe-issues.cjs**: リポジトリスコープのイシュー検索ラッパーを追加し、イシュー番号と作成者ログインのみを返す
- **ci-failure-scan.md**: プロダクション環境のMCPスクリプト設定にラッパーを統合
- **ci-failure-scan.eval.yaml**: ラッパー使用とすべての候補の`issue_read`検査を強制する評価チェックを追加
- **kbe-candidate-reads-grader.mjs**: 候補読み取り結果を検証するグレーダーロジックを拡張
- **kbe-search.test.mjs**: ラッパーと本番環境の動作パリティをテストするテストスイートを大幅拡張
- **ci-failure-scan.lock.yml**: コンパイル済みワークフローアーティファクトを再生成
- **create-kbe.instructions.md**: 候補検査と失敗時閉鎖ガイダンスを更新
- **ci-eval.yml, README.md**: 評価トランスポート使用法を更新
