### [#136332](https://github.com/dotnet/runtime/pull/136332) JIT: Model exceptions of X86Base.DivRem {#136332}
- 作成者: [@EgorBo](https://github.com/EgorBo)
- 作成日時: 2026年10月22日 21:25:31(UTC)
- マージ日時: 2026年10月23日 22:32:14(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-CodeGen-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-CodeGen-coreclr</span></a>
#### 概要
`X86Base.DivRem` と `X86Base.X64.DivRem` は `div`/`idiv` にコンパイルされ、除数がゼロの場合や商がオーバーフローする場合にフォルト（例外）を発生させます。しかしJITはこれらのintrinsicを副作用のない「純粋な」操作としてモデル化しており、`GTF_EXCEPT` が設定されず、`GenTree::OperExceptions` も例外なしを返していました。そのため結果が未使用の場合、結果のデッドストアがDivRemノードごと削除され、例外が失われていました。

本PRでは、これらを Vector の `op_Division` と同様に「特殊な副作用を持つ」ものとして扱い、生成時に `GTF_EXCEPT` を設定し、`OperExceptions` で DivideByZero / Overflow 例外を報告するようにします。これにより、結果が未使用でも例外が保持されます。

#### 変更内容
- `src/coreclr/jit/hwintrinsiclistxarch.h`: `X86Base.DivRem` と `X86Base.X64.DivRem` の両intrinsicに特殊な副作用（special side effect）のフラグを付与
- `src/coreclr/jit/gentree.cpp`: DivRemの生成時に `GTF_EXCEPT` を設定し、`OperExceptions` で算術例外（DivideByZero/Overflow）を報告
- `src/coreclr/jit/fgdiagnostic.cpp`: special side effect のデバッグ検証でDivRemを許可するよう更新
- `src/tests/JIT/Regression_ro_2/Runtime_136303.cs`: ゼロ除算と正常呼び出しの回帰テストを追加（結果を使用する場合と破棄する場合を比較）

#### 概要

原因は `DispatchProxyGenerator.ProxyBuilder.AddMethodImpl` が `TypeBuilder.DefineMethod` に対し、各パラメーターの required custom modifier しか渡しておらず、optional modifier と戻り値型の modifier を渡していなかったことです。`init` アクセサは `void modreq(IsExternalInit)` を返すため、生成されたオーバーライドのシグネチャがインターフェースメソッドと一致しませんでした。戻り値型・パラメーターへの optional modifier や、同一位置に同種の modifier が複数ある場合も同じ例外が発生していました。

修正では、戻り値型の required/optional modifier と各パラメーターの optional modifier も渡すようにしています。Reflection が返す同種 modifier の順序は `DefineMethod` が受け取る順序の逆であるため、要素が複数ある配列は反転しています。

#### 変更内容
- `src/libraries/System.Reflection.DispatchProxy/src/System/Reflection/DispatchProxyGenerator.cs`: `AddMethodImpl` が戻り値型の required/optional custom modifier と各パラメーターの optional custom modifier を `DefineMethod` に渡すよう変更。複数要素の配列は反転 (+12/-2)
- `src/libraries/System.Reflection.DispatchProxy/tests/DispatchProxyTests.cs`: 以下のテストを追加 (+226)
  - `init` プロパティ（通常・ジェネリックインターフェース・インデクサー）のセッター/ゲッター呼び出し
  - 戻り値型またはパラメーターに `modopt(IsConst)` を持つメソッド（Reflection.Emit で構築）
  - 同種 modifier を 2 つ持つメソッド（`IsVolatile` と `IsConst` の両方 required／両方 optional）
  - 戻り値型と複数パラメーターに required/optional modifier が混在するメソッド
- `src/libraries/System.Reflection.DispatchProxy/tests/TestTypes.cs`: テスト用の型を追加 (+18)

#### 概要
CoreCLR WebAssembly 向けに、承認済み API（#130223）`System.Runtime.Intrinsics.Wasm.RelaxedSimd` を実装します。JIT intrinsic と命令、`PackedSimd` を含意する `RelaxedSimd` 命令セットを追加します。Mono は未実装で、`PlatformNotSupported` 実装を使います。

`WasmEnableRelaxedSimd` によるオプトインで有効化されます。有効にすると次の処理が行われます。
- ブラウザホストを `-mrelaxed-simd` で再リンクする
- crossgen2 に `--instruction-set:relaxed-simd` を渡す
- ランタイムプロパティと ILLink substitution で `IsSupported` を設定する

ライブラリテストと JIT HWIntrinsics テストは、この機能を有効にして実行されます。

#### 変更内容
- **API（公開）**: `System.Runtime.Intrinsics.cs`（ref）に `RelaxedSimd` を追加し、`RelaxedSimd.cs` と `RelaxedSimd.PlatformNotSupported.cs` を新設しました。`System.Private.CoreLib.Shared.projitems` も更新しています。
- **JIT/EE**: `hwintrinsiclistwasm.h`、`hwintrinsic.cpp`、`hwintrinsicwasm.cpp`、`instrswasm.h`、`corinfoinstructionset.h`、`readytoruninstructionset.h`、`jiteeversionguid.h` を更新しました。
- **ツール**: `InstructionSetDesc.txt`、`InstructionSetGenerator.cs`、`CorInfoInstructionSet.cs`、`ReadyToRunInstructionSet*.cs`、`r2rdump/WasmDisassembler.cs` を更新しました。
- **VM**: `codeman.cpp` に RelaxedSimd 命令セットの有効化処理を追加しました。
- **PackedSimd**: メンバーごとの `[Intrinsic]` 属性を削除しました（レビュー指摘）。他アーキテクチャや `RelaxedSimd` と同様に型ローダーが報告します。
- **ビルド/リンク**: `eng/native.wasm.targets`、`BrowserWasmApp.CoreCLR.targets`、`ILLink.Substitutions.NoWasmRelaxedSimd.xml`、`ILLink.Substitutions.NoWasmIntrinsics.xml`、`browserhost.cpp` を更新しました。
- **テスト/CI**: `RelaxedSimdTests.cs`、`WasmSIMDTests.cs`、`hardware-intrinsics-wasm.yml`、`tests.wasm.targets` を更新しました。`runtime.yml` では smoke レーンの AOT クロスコンパイラを x64 ビルドにしています。

- **Mono**: インタープリタ側（`transform-simd.c` 等）も変更されています。
