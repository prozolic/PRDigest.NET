#### 概要
Managed ilasm の `/FOLD` オプションで、バイト単位で同一のメソッドボディ（ヘッダーと例外領域を含む）を検出し、既存のボディのオフセットを再利用することでコード重複を排除する機能を実装しました。これにより、IL出力ファイルのサイズ削減が期待できます。

- **Options.cs**: `/FOLD` オプション関連の記述を整理
- **CompilerOptionsTests.cs**: `/FOLD` オプションの動作テストを追加（84行追加）
- **InstructionTests.cs**: 命令テスト関連の更新
- **KNOWN-ISSUES.md**: 既知の問題から関連記述を削除

#### パフォーマンスへの影響
IL出力ファイルサイズの削減が期待できます。同一のメソッドボディを持つメソッド群が存在する場合、ボディを1回のみエミットして複数メソッドから参照されるため、バイナリサイズが縮小されます。実行時パフォーマンスへの直接的な影響はありません。

#### 関連Issue
なし

- 完全なボディ（ヘッダー・例外領域を含む）がバイト単位で同一である場合にのみ再利用されるため、正確性が保証されます
- `/FOLD` オプションが無効な場合は既存の動作が保持されます

### [#132346](https://github.com/dotnet/runtime/pull/132346) Convert managed ilasm to use ANTLR actions instead of visiting the parse tree {#132346}
- 作成者: [@jkoritzinsky](https://github.com/jkoritzinsky)
- 作成日時: 2026年08月14日 22:44:43(UTC)
- マージ日時: 2026年10月02日 03:59:48(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-ILTools-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-ILTools-coreclr</span></a>
#### 概要
managed ilasmをANTLRアクション駆動型パースに変換し、フルパースツリーの構築を廃止することで、メモリ使用量と実行時間を大幅に削減しました。特に大規模なテストアセンブリ（HardwareIntrinsics AVX512、HugeArray）でメモリ効率が改善され、x86でのOOM問題を解決しています。また、ILAssemblerライブラリの公開API表面をref-assemblyコントラクトで制限し、ANTLR生成型を内部実装に留めました。

#### 変更内容
- **DocumentCompiler**: `UnbufferedTokenStream`を使用し、パースツリー構築を無効化。`GrammarActions`を通じたアクション駆動型パースに切り替え
- **Ref-assemblyコントラクト**: `src/tools/ilasm/src/ILAssembler/ref/`配下に新規プロジェクト追加。公開API（DocumentCompiler、Diagnostic、CompilationResult等）をコントラクト型として定義
- **GrammarActionsシリーズ**: 型参照、メソッドヘッダ、メソッドボディ、マーシャリング、マニフェスト、カスタム属性など、複数の`GrammarActions`ファイルで文法アクションを実装
- **セマンティック値モデル**: `CILParser.SemanticValues.*`で署名・メソッドボディ・マーシャリング・マニフェスト・カスタム属性の型安全なモデルを追加
- **StringCharStream**: `AntlrInputStream`のオーバーヘッドを回避するための軽量`ICharStream`実装
- **エラー許容性向上**: truncated/malformedな入力に対する例外の発生を防ぎ、診断結果を生成
- **状態漏洩防止**: 複数ドキュメント/スコープ間での状態漏洩を防止する拡張テスト
