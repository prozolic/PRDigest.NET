### [#134750](https://github.com/dotnet/runtime/pull/134750) Fix NRE in dynamic multi-dim array indexing under trimming {#134750}
- 作成者: [@lewing](https://github.com/lewing)
- 作成日時: 2026年09月27日 18:48:22(UTC)
- マージ日時: 2026年09月27日 21:14:31(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Infrastructure-libraries/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Infrastructure-libraries</span></a>
#### 概要
トリミング時に動的多次元配列インデックス操作で `NullReferenceException` が発生する問題を修正しました。C#ランタイムバインダーが動的配列インデックスを処理する際、リフレクションで `Expression.ArrayIndex(Expression, Expression[])` メソッドを検索しますが、トリマーが未使用と判定して削除してしまい、検索結果が `null` になることが原因です。`[DynamicDependency]` 属性を追加してこのメソッドをトリミング時に保持させることで対応しました。

#### 変更内容
- **ExpressionTreeRewriter.cs**: `VisitARRAYINDEX` メソッドに `[DynamicDependency]` 属性を追加し、`Expression.ArrayIndex(Expression, Expression[])` オーバーロードがトリミング時に削除されないようにしました。
- **Conformance.dynamic.dynamicType.basic.cs**: `array005`/`array006` テストの `[ActiveIssue]` 属性を削除しました（この修正により問題が解決されたため）。

#### パフォーマンスへの影響
影響なし

#### 関連Issue
[#134265](https://github.com/dotnet/runtime/issues/134265)

#### その他
- Microsoft.CSharp は現在トリム互換ではない（設計上の制限）ため、この修正は既存の `[RequiresUnreferencedCode]` アノテーションの下で、リフレクション基盤のメソッド検索を強化するための局所的な対応です。
- 同じパターンは既に `ComInterop/VariantArray.cs` で使用されています。
- 検証済み：`EnableAggressiveTrimming=true TestTrimming=true` の条件下で、修正前は `array005` で NRE が発生し、修正後は 2913/2913 テストが合格しました。

### [#134699](https://github.com/dotnet/runtime/pull/134699) \[interpreter\] Resolve open virtual delegates invoked through the shuffle thunk \(wasm, Apple mobile\) {#134699}
- 作成者: [@lewing](https://github.com/lewing)
- 作成日時: 2026年09月26日 04:39:30(UTC)
- マージ日時: 2026年09月27日 17:13:04(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/arch-wasm/index.html"><span style="background-color: #eb6420; color: #ffffff; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">arch-wasm</span></a> <a style="text-decoration:none;" href="../../labels/os-maccatalyst/index.html"><span style="background-color: #fef2c0; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">os-maccatalyst</span></a> <a style="text-decoration:none;" href="../../labels/area-CodeGen-Interpreter-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-CodeGen-Interpreter-coreclr</span></a>
#### 概要
interpreter を使用するプラットフォーム（browser-wasm、macOS/iOS/tvOS）で、オープン仮想デリゲートをコンパイル済みコードから呼び出した際に発生するクラッシュを修正します。問題は IL shuffle thunk が `CID_VirtualOpenDelegateDispatch` を `calli` 経由で呼び出す際、隠し引数（arm64 の `x11`、wasm の portable entry point）が正しく渡されていないことが原因でした。

#### 変更内容
- **src/coreclr/vm/interpexec.cpp**: `INTOP_CALLI` 命令で `CID_VirtualOpenDelegateDispatch` を認識し、デリゲート（shuffle thunk の `this`）とターゲットの `this` 引数から仮想ターゲットを解決してから `CALL_INTERP_METHOD` で処理。`INTOP_CALLDELEGATE` と `INTOP_CALLI` で共通の `ResolveOpenVirtualDelegateTarget` メソッドを利用。
- **src/coreclr/vm/comdelegate.cpp**: 関連するコメント更新と Issue リンク追加。
- **src/libraries/System.Runtime/tests/System.Runtime.Tests/System/DelegateTests.cs**: オープン仮想デリゲート呼び出しの回帰テスト追加（クラスオーバーライド、ボックス化構造体、列挙型、インターフェース dispatch）。browser Mono AOT はインターフェース関連テストを無効化。
- **src/libraries/tests.proj**: browser CoreCLR ReadyToRun レーンで `System.Linq.Expressions.Tests` を再有効化。

#### パフォーマンスへの影響
影響なし

#### 関連Issue
[#134261](https://github.com/dotnet/runtime/issues/134261)、[#134720](https://github.com/dotnet/runtime/issues/134720)、[#134733](https://github.com/dotnet/runtime/issues/134733)、[#134707](https://github.com/dotnet/runtime/issues/134707)

#### その他
- この修正は interpreter 側のワークアラウンドで、根本的な fix は shuffle thunk 側で対応予定（#134733）。
- 検証結果：browser-wasm CoreCLR ReadyToRun で System.Linq.Expressions.Tests が 35,116 テスト実行、System.Runtime.Tests DelegateTests が 58 テスト実行、maccatalyst-arm64 で System.Runtime.Tests が 79,181 テスト実行で、すべて成功。
- 内部実装の変更（interpreter 側のワークアラウンド）であり、公開 API への影響なし。
