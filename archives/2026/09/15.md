### [#132927](https://github.com/dotnet/runtime/pull/132927) Replace CoreCLR PAL wait subsystem {#132927}
- 作成者: [@jkoritzinsky](https://github.com/jkoritzinsky)
- 作成日時: 2026年08月29日 18:53:54(UTC)
- マージ日時: 2026年09月15日 21:27:20(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-VM-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-VM-coreclr</span></a>
#### 概要
CoreCLR の PAL（Platform Abstraction Layer）待機サブシステムを廃止し、Unix ネイティブ待機を単一ハンドルイベント待機に統一します。NativeAOT イベント実装を共有ランタイムに移動し、Windows ではネイティブ API を、Unix では pthread ベースの実装を使用する新しい `CLREventBase` を導入します。`PAL_Sleep` は Windows では `Sleep` に、Unix では EINTR セーフな `nanosleep` にバックアップされます。

#### 変更内容
- **新規 API**: `minipal_sleep()` を minipal/time に追加（クロスプラットフォーム sleep）
- **共有イベント実装**: `CLREventBase` を `src/coreclr/runtime` に移動し、Windows/Unix 実装を提供
- **PAL 機能削除**: 従来の PAL イベント、sleep、スレッド待機、同期マネージャー、コントローラー、キャッシュを削除
- **コアランタイム更新**: CoreCLR/NativeAOT/デバッガーコードを共有 `CLREventBase` に移行
- **Unix スレッド終了**: Unix で手動リセットスレッド終了イベントを追加；Windows は OS スレッドハンドルで継続
- **PAL テスト更新**: 256 個の既存テストパスをまたは新規 `RuntimeEvent` テストで `minipal_sleep` と完了カウンター方式に統一
- **GC イベント**: `GCEvent` 作成 API を OS 非依存に簡略化
- **デバッガー**: `HANDLE` ベースのイベント実装を `CLREvent`/`CLREventBase` に置き換え

#### パフォーマンスへの影響
影響なし（リファクタリングによる互換性維持、パフォーマンス特性は変わらず）

#### 関連Issue
なし

#### その他
**内部実装変更**: このPRは PAL 内部実装の廃止であり、パブリック API の直接的な破壊的変更はありません。ただし、Copilot のコード審査で中程度の懸念が 5 件報告されています：
- `CreateManualEventNoThrow(false)` の失敗判定が OOM に限定されていない可能性
- デバッガーの `canary.cpp` で 1 引数 `Wait()` の使用が EE（Execution Engine）認識の待機をバイパスする可能性
- `rcthread.cpp` の EE 認識イベントで 1 引数 `Wait(INFINITE)` 呼び出しの問題

テスト結果：PAL テストスイート 256 パス、0 失敗
