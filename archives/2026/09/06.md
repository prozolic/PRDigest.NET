### [#133312](https://github.com/dotnet/runtime/pull/133312) \[Mono\]\[browser\] Quarantine double Min/Max NaN payload tests {#133312}
- 作成者: [@lewing](https://github.com/lewing)
- 作成日時: 2026年09月05日 20:59:49(UTC)
- マージ日時: 2026年09月06日 01:18:57(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/arch-wasm/index.html"><span style="background-color: #eb6420; color: #ffffff; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">arch-wasm</span></a> <a style="text-decoration:none;" href="../../labels/area-System.Numerics/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-System.Numerics</span></a>
#### 概要
Mono browser-WASM環境で、double型の`Max`/`Min`ジェネリック数学テストケースのNaN符号・ペイロードテストをQuarantine（隔離）します。共有テストメソッドやデータセットを分割せず、`MaxDouble`と`MinDouble`に条件付きチェック（`PlatformDetection.IsMonoRuntime && PlatformDetection.IsWasm`）を追加することで、Mono browser-WASM環境でのみ該当テストケースを除外します。他のランタイムではすべてのMax/Minカバレッジは変更されません。

#### 変更内容
- **src/libraries/Common/tests/System/GenericMathTestMemberData.cs**: `MaxDouble`と`MinDouble`のNaN符号・ペイロード行に条件付きフィルタリングを追加。Mono browser-WASM環境でのみこれらの行を除外します。
- **src/libraries/System.Runtime/tests/System.Runtime.Tests/System/DoubleTests.GenericMath.cs**: 新しい理論テストメソッドを追加してNaN符号・ペイロードケースを隔離（内容は提供情報に記載なし）

#### パフォーマンスへの影響
影響なし

#### 関連Issue
[#133311](https://github.com/dotnet/runtime/issues/133311)

#### その他
**Copilotからの指摘事項:**
1. **テストカバレッジの懸念**: NaN符号・ペイロード行を`MaxDouble`/`MinDouble`から移動させることで、これらの共有データセットを使用する他のテストスイート（Math.cs、Vector*テストなど）のカバレッジが低下する可能性があります。
2. **プラットフォーム判定の曖昧性**: `PlatformDetection.IsWasm`はWASI（`IsBrowser || IsWasi`）も含むため、実際の隔離スコープが説明（browser-WASM）より広くなっている可能性があります。WASI環境の意図が明確でない場合、`IsBrowser`への変更が検討されています。

検証済み: Mono browser-WASM環境で17/17のMaxTest、17/17のMinTestケースが合格

### [#133079](https://github.com/dotnet/runtime/pull/133079) JIT: Expand REFANYTYPE QMARK before physical promotion {#133079}
- 作成者: [@jakobbotsch](https://github.com/jakobbotsch)
- 作成日時: 2026年09月02日 12:41:07(UTC)
- マージ日時: 2026年09月06日 17:00:36(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-CodeGen-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-CodeGen-coreclr</span></a>
#### 概要
REFANYTYPE null チェックで生成される `GT_QMARK` が physical promotion 前の早期段階で展開されるよう修正しました。これまで QMARK 腕内の struct ストアは physical promotion でサポートされていませんでしたが、この変更により QMARK を早期展開対象にマークすることで、unsupported な promotion/readback シナリオを回避します。

#### 変更内容
- **src/coreclr/jit/importer.cpp**: REFANYTYPE null チェック QMARK を早期展開可能としてマークし、`OMF_HAS_EARLY_QMARKS` フラグを設定
- **src/coreclr/jit/morph.cpp**: `compQmarkRationalized` フラグを遅延 QMARK 展開後のみ設定するよう修正
- **src/coreclr/jit/promotion.cpp**: DEBUG ビルド時に、promotion 対象の store/retbuf 定義が QMARK 腕内に存在しないことを検証するアサーション追加
- **src/tests/JIT/Directed/physicalpromotion/readbackbeforeqmark.cs**: REFANYTYPE を含むリグレッションテスト追加

#### パフォーマンスへの影響
影響なし。本変更は JIT コンパイル時の QMARK 処理タイミングを調整するもので、生成コードのランタイム動作には影響しません。

#### 関連Issue
[#133047](https://github.com/dotnet/runtime/issues/133047)

#### その他
- 本変更は JIT コンパイラの内部実装（public API に変更なし）
- REFANYTYPE は特殊なケースのため、physical promotion ロジックを複雑化させず早期展開で対応する設計
- DEBUG チェックにより将来の regression を防止
