#### 概要

- **インタープリタサポート**: `intops.def`に`INTOP_MINMAX_NATIVE_*`オペコード追加、`interpexec.cpp`に実装追加により、JIT非対応環境でのフォールバック機能を保証。
- **x86スカラー変換の修正**: `ConvertToIntegerNative`がAVX512対応時は飽和パスではなくAVX512命令を使用するよう修正。
- **JIT/EE/R2R/SuperPMI全体の整合性**: ICoreJitInfo インターフェース、ThunkGenerator、MethodContextなど複数レイヤーでISA依存関係フラグを伝播。

#### 概要
WebAssembly の JS/wasm 境界でポインタの符号が保持されず、2GB を超えるアドレスが負の数として表示される問題を修正します。このバックポートは main ブランチの PR #121221 をベースとしており、暗号、デバッガ、WebSocket、イベントパイプ、jiterpreter などの複数の領域でポインタを符号なし整数として扱うように修正します。

mono ブラウザランタイムの JavaScript 側で `>>> 0` や `fixupPointer` を使用してポインタ値を符号なし化し、wasm のメモリ操作時の無言の破損（例：`RandomNumberGenerator.Fill` がゼロバッファを返す、jiterpreter の無効なモジュール生成）を防ぎます。

#### 変更内容
- **crypto.ts**: エントロピーバッファポインタを符号なしに強制
- **debug.ts / diagnostics/*.ts**: デバッガおよび診断メッセージバッファビューで符号なしオフセットを使用
- **jiterpreter*.ts**: ポインタ値を符号なしに強制し、wasm コード生成時の無効なエンコーディング防止。`constantSlots` 機能を削除
- **marshal.ts / memory.ts / strings.ts / web-socket.ts / roots.ts / startup.ts**: ヒープアクセスおよびメモリビュー作成時にすべてのポインタ・オフセットを符号なし化
- **MemoryTests.cs / MemoryTest.cs / main.js**: 2GB を超える領域でのデータ整合性を検証するテストシナリオを拡張

#### パフォーマンスへの影響
2GB 以下のヒープでは `>>> 0` 強制はノー・オプです。4GB ヒープの最大化は `<EmccMaximumHeapSize>` と `wasm-tools` ワークロード経由のネイティブリンク時のみ有効化されるため、影響のあるシナリオはオプトインです。
