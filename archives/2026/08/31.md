- 作成日時: 2026年08月29日 22:52:35(UTC)
- マージ日時: 2026年08月31日 23:05:44(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/community-contribution/index.html"><span style="background-color: #c2e0c6; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">community-contribution</span></a> <a style="text-decoration:none;" href="../../labels/area-NativeAOT-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-NativeAOT-coreclr</span></a>
#### 概要
NativeAOT のCOFF リロケーション処理におけるメモリ割り当てオーバーヘッドを削減します。`CoffRelocation`をヒープオブジェクトから12バイトの不変値型構造体に変更し、リロケーション列挙時に`ref readonly`で反復処理することで、数千万のリロケーションレコード処理時のメモリ使用量とGC圧力を大幅に軽減します。

#### 変更内容
- **CoffObjectWriter.cs**: `CoffRelocation`をクラスから`internal readonly struct`に変更。`VirtualAddress`、`SymbolTableIndex`、`Type`フィールドを保持し、12バイトのマネージレイアウトで`List<CoffRelocation>`に格納。`Write`メソッドは引き続き10バイトのCOFF形式を出力。リロケーション発行時に`CollectionsMarshal.AsSpan`と`ref readonly`反復を使用してディフェンシブコピーを回避。
- **テスト追加**: `CoffObjectWriterTests.cs`でリロケーションエンコーディング、オーバーフロー記録動作、アーキテクチャ別リロケーションタイプマッピングを検証。

#### パフォーマンスへの影響
**ベンチマーク結果（500万リロケーション処理）:**
- マネージメモリ割り当て: **-92.9 MiB (-31.57%)**
- ヒープリロケーションオブジェクト: 500万個 → 0個
- Gen 0/1/2 GC収集回数: 各-11/-11/-3回
- ピークプライベートバイト: **-93.0 MiB**
- ピークワーキングセット: **-127.9 MiB**
- リロケーション変換時間: **-83.47%** (487.66ms → 80.60ms)

**実RDM実績（4,100万リロケーションレコード）:**
- マネージメモリ割り当て: 0.51～0.67 GiB削減
- 出力ファイル: 同一SHA-256ハッシュで3.7 GiB

改善点は割り当てとオブジェクト密度。エンドツーエンドのコンパイル時間改善は確認されていません。

#### 関連Issue
なし

#### その他
- 内部実装の変更で、公開APIへの影響なし
- 既存のCOFF形式互換性を保証（10バイトのワイヤエンコーディング変更なし）
- `Write`メソッドが`readonly`マークされていないため、`ref readonly`反復でディフェンシブコピーが発生する可能性がありレビュー指摘あり
- ビルド検証済み（clr.aot+libs、ILCompiler.Compiler.Tests 22/22合格、NativeAOT smoke tests 28/28合格）
