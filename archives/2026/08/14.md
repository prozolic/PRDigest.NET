#### 概要
`XmlSerializer`のリフレクションパスでの配列要素シリアライゼーションを最適化しました。従来は配列を`IList`として扱うことで`Array.GetValue`を呼び出していましたが、明示的な配列パスを追加して直接列挙することで、ループ内のオーバーヘッドを削減します。シリアライゼーション出力の動作は変わりません。

```csharp
Array? choiceArray = choiceSources as Array;

if (o is Array array)
{
    IEnumerator e = array.GetEnumerator();
    int c = 0;
    while (e.MoveNext())
    {
        object ai = e.Current;
        object? choiceSource = choiceArray?.GetValue(c++);
        WriteElements(ai, choiceSource, elements, text, choice, true, true);
    }
    return;
}
```

#### 変更内容
- **ReflectionXmlSerializationWriter.cs**: `WriteArrayItems`メソッドに`Array`型の明示的なチェック分岐を追加。配列の場合は`Array.GetEnumerator()`で直接反復し、IList経由でのインデックスアクセスを避ける。`choiceSources`キャストを一度だけ実行して`choiceArray`に保存し、配列/リスト/列挙可能パス全体で再利用
- **XmlSerializerTests.cs**: 配列シリアライゼーションの動作を検証するテストケース（82行）を追加
- **SerializationTypes.RuntimeOnly.cs**: テスト用の型定義（46行）を追加

#### パフォーマンスへの影響
改善あり。配列要素へのアクセス時に`IList`インターフェース経由でのインデックスアクセスを回避し、直接配列列挙を使用することで、特にプリミティブ型配列における`Array.GetValue`呼び出しのオーバーヘッドを削減します。ベンチマーク結果の記載はありませんが、ループ内での1要素あたりの処理がより効率的になります。

[#67221](https://github.com/dotnet/runtime/issues/67221)

#### その他
