### [#132270](https://github.com/dotnet/runtime/pull/132270) Fix TryParsePartial under-reporting charsConsumed for leading whitespace {#132270}
- 作成者: [@Copilot](https://github.com/apps/copilot-swe-agent)
- 作成日時: 2026年08月13日 10:57:09(UTC)
- マージ日時: 2026年08月13日 22:56:30(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-VM-coreclr/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-VM-coreclr</span></a>
#### 概要
`INumberBase<T>.TryParsePartial` が、フォーマットプロバイダーのサイン記号が `"+"`/`"-"` 以外の場合（`sv-SE`、`fi-FI`、アラビア語/ヘブライ語ロケールなど約96の言語）に、先頭の空白を `charsConsumed` に含めずに報告していたバグを修正します。この問題により、呼び出し元が返された消費文字数で位置を進めると、既に読み込んだ数値の途中に巻き戻ります。

```csharp
int.TryParsePartial(" 5", NumberStyles.Integer, new CultureInfo("sv-SE"), out int v, out int consumed);
// 修正前: v = 5, consumed = 1 (期待値: 2)
// 修正後: v = 5, consumed = 2
```

#### 変更内容
- **src/libraries/System.Private.CoreLib/src/System/Number.Parsing.cs**: `Number.TryParseBinaryIntegerStyle` で、サイン記号のマッチング時に元の `value` スパンのインデックスをスライス操作で失わないよう、スライスを `remaining` 局所変数に限定。これにより、先頭空白のオフセットが保持され、正確な `elementsConsumed` が計算されます。
- **src/libraries/System.Runtime/tests/System.Runtime.Tests/System/Int32Tests.cs**: `TryParsePartial` テストケースを追加（先頭空白のみ、`+` 付き、マルチバイト負号、末尾空白の組み合わせ）
- **src/libraries/System.Runtime/tests/System.Runtime.Tests/System/UInt32Tests.cs**: 同様にテストケースを追加

#### パフォーマンスへの影響
影響なし

#### 関連Issue
[#132261](https://github.com/dotnet/runtime/issues/132261)

#### その他
- 影響範囲: 全バイナリ整数型（`int`、`uint`、`long`、`ulong` など）で同じコードパスを使用するため、すべてのバイナリ整数型に適用
- 互換性: 修正前の動作は仕様外のバグであり、正しい `charsConsumed` を返すことで互換性が向上
- 非部分解析の呼び出し元（`Enum`、`Version`）は `elementsConsumed` を破棄するため影響なし
- `BigInteger.TryParsePartial` の同様のバグは本修正では対象外とし、別途対応予定

#### 変更内容
- **`NativeMarshallingAttributeInfo`** — `SupportsManagedToUnmanagedMarshalling`/`SupportsUnmanagedToManagedMarshalling`（初期値`true`）の2つの`init`プロパティを追加。マーシャラーがどの方向をサポートするかを示します。
- **`ComInterfaceMarshallingInfoProvider`** — `[GeneratedComInterface(Options = …)]`から`ComInterfaceOptions`を読み込み、対応フラグを設定（内部的には`int`として読込、`0x1`=CCW、`0x2`=RCW）。
- **`AttributedMarshallingModelGeneratorResolver.CreateCustomNativeTypeMarshaller`** — マーシャリング方向が必要なオプションでサポートされているかを検証し、未サポートの場合は`SYSLIB1051`エラーを返す。
- **リソース文字列** — `Strings.resx`に新規の2つエラーメッセージと対応する多言語`.xlf`ファイルの更新。
- **ユニットテスト** — `LibraryImportGenerator.UnitTests/CompileFails.cs`と`ComInterfaceGenerator.Unit.Tests/CompileFails.cs`に、各マーシャリング方向と制限オプションのカバレッジを追加。
