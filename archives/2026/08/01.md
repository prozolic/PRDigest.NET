### [#131682](https://github.com/dotnet/runtime/pull/131682) Exclude WebSocketException from BinaryFormatter blob ToString comparison {#131682}
- 作成者: [@jtschuster](https://github.com/jtschuster)

#### 概要
`WebSocketException`のネイティブエラーコードがスレッド状態に依存して変化するため、BinaryFormatterのテストにおいて`ToString()`比較から除外する変更です。`Win32Exception`を継承する`WebSocketException`は`Marshal.GetLastPInvokeError()`から`NativeErrorCode`を設定するため、ライブテストオブジェクトと保存されたblobで異なる文字列表現を持つことがあります。同様の除外は既に`System.Resources.Extensions`で実装されており、ここではそれをミラーリングします。

#### 変更内容
- **src/libraries/System.Runtime.Serialization.Formatters/tests/EqualityExtensions.cs**
  - `System.Net.WebSockets`名前空間をインポート
  - `EqualityExtensions.IsEqual(Exception, ...)`メソッドの`ToString()`等値性アサーションから`WebSocketException`を除外

### [#131627](https://github.com/dotnet/runtime/pull/131627) Fix cDAC DBI cleanup lifetime {#131627}
- 作成者: [@rcj1](https://github.com/rcj1)
- 作成日時: 2026年07月31日 00:51:28(UTC)
- マージ日時: 2026年08月01日 02:32:35(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-Diagnostics-cdac/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-Diagnostics-cdac</span></a>
#### 概要
cDAC（managed diagnostic access component）のライフタイム管理を修正し、DBI（Debugger Bind Interface）がDAC（Diagnostic Access Component）をアンロードする前に、cDAC管理下のCOM インターフェースをアンロードするための明示的な`Destroy()`メソッドを追加しました。これにより、caller所有のCOMオブジェクトの確定的なクリーンアップが可能になります。内部stackwalking cDAC テストの修正を含みます。

#### 変更内容
- **COM契約の拡張**：`dacdbi.idl`に`Destroy([out] IUnknown** ppLegacyCleanup)`メソッドを追加し、管理下のCOMインターフェースのクリーンアップ用途で使用
- **ネイティブ実装**：`dacdbiinterface.h`と`dacdbiimpl.cpp`に対応する仮想メソッドを追加し、ネイティブ実装では単にnullを返す
- **DBI teardownロジック**：`process.cpp`の`CordbProcess::FreeDac`を更新し、DAC モジュール アンロード前に`Destroy`を呼び出す
- **managed cDAC実装**：
  - `IDacDbiInterface.cs`で管理COM投影にDestroyメソッドを追加
  - `DacDbiImpl.cs`で`Destroy`を実装し、`FinalRelease()`で unique COM wrappers を確定的にリリース。legacy 実装がある場合はDBI管理用のCOMポインタを返す
  - `Entrypoints.cs`で`UniqueComInterfaceMarshaller<>`を使用し、caller所有COM入力に対して確定的なクリーンアップを実現。エラーパスで`FinalRelease()`を呼び出し

#### パフォーマンスへの影響

#### その他

### [#131245](https://github.com/dotnet/runtime/pull/131245) Support unsafe evolution in LibraryImportGenerator {#131245}
- 作成者: [@EgorBo](https://github.com/EgorBo)
- 作成日時: 2026年07月23日 00:02:23(UTC)
- マージ日時: 2026年08月01日 16:06:21(UTC)
- ラベル: <a style="text-decoration:none;" href="../../labels/area-System.Runtime.InteropServices/index.html"><span style="background-color: #d4c5f9; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">area-System.Runtime.InteropServices</span></a> <a style="text-decoration:none;" href="../../labels/linkable-framework/index.html"><span style="background-color: #1ae80b; color: #000000; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">linkable-framework</span></a> <a style="text-decoration:none;" href="../../labels/source-generator/index.html"><span style="background-color: #3988A9; color: #ffffff; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">source-generator</span></a> <a style="text-decoration:none;" href="../../labels/reduce-unsafe/index.html"><span style="background-color: #0F6E51; color: #ffffff; display: inline-block; padding: 0 7px; font-size:12px; font-weight:500; line-height:18px; border-radius:2em; border:1px solid transparent;">reduce-unsafe</span></a>
#### 概要
`[LibraryImport]` 属性を使用するメソッドに対して、C# の unsafe evolution（更新されたメモリ安全性ルール）への対応を追加しました。新しいルールが有効な場合、すべての `[LibraryImport]` メソッドは明示的に `safe` または `unsafe` 修飾子を要求します。また、既存コードを移行するためのアナライザーとコード修正ツールが含まれています。

#### 変更内容

**LibraryImportGenerator（内部実装）:**
- `LibraryImportGenerator.cs` と `DownlevelLibraryImportGenerator.cs` が、生成される wrapper 内の `extern` local 関数に安全性修飾子を鏡映
- `LibraryImportDiagnosticsAnalyzer` と `DownlevelLibraryImportDiagnosticsAnalyzer` で新診断 `SYSLIB1064` を追加し、更新されたルール下で安全性修飾子の明示を要求（すべての P/Invoke 形状で統一的に適用）

**アナライザー・コード修正（ツール）:**
- `LibraryImportRequiresExplicitSafetyAnalyzer.cs` が `IL5007` 診断を追加し、安全性契約のないメソッドを検出（opt-in 無関係に発火、マイグレーション用）
- `AddUnsafeToLibraryImportCodeFixProvider.cs` が `IL5007` を修正し、デフォルトで `unsafe` を付与
- `ConvertToLibraryImportFixer.cs` が `[DllImport]` を `[LibraryImport]` に変換する際、`unsafe` 修飾子を保持

**共有拡張・リソース:**
- `MemorySafetyRules.cs` に安全性修飾子検出と `updated-memory-safety-rules` フィーチャーフラグ検出ヘルパーを追加
- 複数言語（de, es, fr, it, ja, ko, pl, pt-BR, ru, tr, zh-Hans, zh-Hant, cs）のローカライズ文字列を更新

**テスト:**
- `UnsafeCodeGeneration.cs` を拡張し、`safe`/`unsafe` 鏡映とフィーチャーフラグ下での診断を網羅

#### パフォーマンスへの影響
影響なし

#### 関連Issue
[#131451](https://github.com/dotnet/runtime/issues/131451)

#### その他
- **互換性**: unsafe-v1 では変更なし。unsafe-v2 ルール有効時のみ適用
- **デザイン選択**: 代替案として生成コードから `unsafe` を出すことも検討されましたが、エラーがユーザーの宣言ではなく生成ファイルに現れるため、コード修正が不可能になることから却下
- **既知の制限**: Roslyn が非 `extern` メンバーでの `safe` をまだ許可していない（CS9388）。従って `safe` は生成が直接 forwarder の場合のみ記述可能
